## 2. 必须整改

### QA-134-01：新增专项未满足任务书的NPC端到端覆盖

`tests/test_native_npc_progression_routes_scene.gd` 当前缺少：

1. 从研究所NPC进入 `ResearchPanel` 后继续完成资助、产量任务、购买三条成功路径。
2. 从同一NPC入口覆盖至少一条研究所失败原子性路径。
3. 从公主NPC对话领取周日礼物并验证重复/失败不错误结算。
4. 周一和周二分别从日常官NPC入口完成一种材料交付。

现有 `test_native_research_flow_scene` 使用 `main._toggle_research()` 直接打开窗口，只能作为相邻回归，不能替代任务书要求的“从地图NPC入口开始”的验收。

影响：当前49项全绿，但不能证明上述原生NPC链路端到端成立。

### DQ-134-02：注册表证据引用大部分为实现自证

19个选项中有16个的：

- `evidence_source` 指向 `res://scripts/main_original.gd`。
- `implementation_path` 也指向同一实现文件。

专项测试只验证token存在于实现代码，因此能够证明“代码里写了这个action”，不能证明“原SWF确实存在这个选项”。`swf_evidence` 只是不可机检的自由文本。

这不符合任务书“先反查后编码”和“evidence_source + evidence_tokens可验证”的证据要求。

影响：证据链为循环自证；后续无图像模型无法区分原版事实、Godot实现和项目改版。

### DQ-134-03：元帅证据缺口登记不完整

原SWF `sprite1184` 同时包含：

- `军情查询`：BOSS行踪。
- `关于军衔`：军功来源和各级军衔说明。

当前注册表只把“军情查询”列入缺口，没有登记“关于军衔”。同时当前Godot选项“国王消息”不能作为原版“军情查询”的等价证据。

本次不要求扩大玩法实现，但注册表必须如实记录两个独立缺口，不能把“军情/消息分支”模糊合并。

### DOC-134-04：文档测试总数仍不一致

`开发进度.md` 顶部当前仍写：

> 最近一次回归覆盖48个测试场景

而当前正式基线为49。开发方报告“文档49”与文件事实不一致。

## 3. PM对三个待决项的决定

### DEC-134-01：75,000,000金币档

决定：保留在VIP便捷聚合窗，视为改版便捷档；不加入首相原版NPC流程。

要求注册表/文档明确标注：

- 原版可确认规则是每750,000金币换1点功勋。
- 75,000,000只是便捷批量操作，不得宣称为原版选项。

### DEC-134-02：日常官材料与奖励冲突

决定：v1.34整改不修改数值，继续保持当前项目数据：

- 魔魂晶石：500功勋。
- 灵魂王：2,000功勋。

原因：v1.34任务明确禁止改数值；当前差异属于“原版证据与既有项目规则的冲突”，不是入口路由缺陷。

要求在注册表中把它标为 `intentional_divergence` 或等价结构，分别写明：

- 原SWF文本证据。
- 当前项目实际规则。
- PM决定“本版本保持项目规则”。

后续如需恢复原版灵魂晶石和统一500功勋，应单独发布数值迁移任务，并评估存档/物品来源影响，不并入本整改。

### DEC-134-03：元帅军情查询与关于军衔

决定：本次整改只补齐证据缺口，不增加玩法入口。

原因：两项不属于任务书列出的六处路由修正；直接增加会扩大已交付版本范围。后续另行安排NPC细节补齐，不并入v1.35全地图演员审计。
