## 2. 阻断准入的问题

### QA-001：全量测试执行器仍可能把未执行完的测试判为通过

严重度：中  
置信度：高  
影响范围：所有后续自动化回归

`run_tests.ps1` 当前把场景 `--quit-after` 从 600 增加到 1200，但每个场景完成后仍只检查：

- Godot 进程退出码。
- `SCRIPT ERROR:` / 非忽略 `ERROR:`。

执行器没有要求测试日志出现该场景自己的 `PASS ...` 行，并且在判定前就删除日志。

因此，1200 帧只能降低 `test_scene_battle_scene` 当前机器上的提前终止概率，不能从机制上消除假通过。只要未来某个测试因更慢、等待条件未满足或卡在断言前，被 `--quit-after` 正常终止且没有脚本错误，runner 仍会计为成功。

本次PM/SE使用额外的强制PASS循环验证了当前48项确实全部跑完，所以这不是当前玩法失败；它是持续集成可信度问题，必须在进入下一版本前修复。

### DQ-002：v1.33导致无图像证据注册表中的数字行号大面积漂移

严重度：中  
置信度：高  
影响范围：无图像模型的资源定位、后续资源清理和证据审计

v1.32注册表大量 `image_assets.evidence_source` 使用 `main_original:<数字行号>`。v1.33在文件顶部删除4项 preload/成员，并在 `_build_panels()` 中继续删除代码，导致后续行号整体变化。

独立检查结果：

- 含 `main_original:<数字行号>` 的资源证据：55项。
- 当前所指行/范围仍包含对应 `image_id`：1项。
- 已漂移或不再直接命中对应资源：54项。

示例：

- `image_0038` 登记 `main_original:1577-1578`，当前实际引用位于1564～1567附近。
- `image_0049` 登记 `main_original:1571`，当前实际引用位于1558、1561、1624、1652。
- `image_0455` 登记 `main_original:99`，当前实际引用位于95。
- 顶部HUD组件登记 `main_original:142-151`，v1.33后同一构建代码也已前移。

`test_swf_evidence_registry_scene` 继续通过，是因为它验证文件/资源/作用域引用存在，但不验证 `evidence_source` 中的数字行号仍准确。注册表的核心用户不能识别图片，失效定位会直接降低交接证据的可信度。

建议不要只批量重算一次行号。更稳定的修复是改成“文件路径 + 可搜索token/符号”的结构化定位，例如：

```json
{
  "path": "res://scripts/main_original.gd",
  "token": "image_0038"
}
```

UI组件优先使用现有 `godot_symbol`；资源优先使用文件路径和 `image_id` token。数字行号可作为非权威备注，但不能继续作为唯一定位方式。
