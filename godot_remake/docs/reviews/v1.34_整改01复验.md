## 2. 新发现的阻断问题

### DQ-134-05：研究所NPC与研究所窗口的SWF scope识别错误

整改证据文件把研究所范围写为：

- `sprite827`：研究所。
- “进入研究所（research NPC对话 -> 专属窗口）”。

PM/SE独立执行：

```powershell
python .\work\dump_sprite_actions.py 魔域1.03_v9.swf 827
python .\work\dump_sprite_actions.py 魔域1.03_v9.swf 1174
```

确认：

- `sprite827`是研究所专属窗口，包含技术、库存、售价、资助、购买等窗口逻辑。
- `sprite1174`才是研究所NPC对话，原版选项明确包含：
  - `进入`
  - `研究所的当前信息`
  - `关于2008奥运使者`
  - `提高产量任务`

当前证据文件遗漏 `sprite1174`，并把NPC入口错误归因于 `sprite827`。因此“现有ResearchPanel路由与原版证据一致、无需校正”的结论不成立。

影响：

- 当前Godot研究所NPC只有“进入研究所/离开”。
- 原版三个NPC对话分支仍缺失。
- 注册表把研究所单一入口分类为 `native_confirmed`，但其证据不足且标签不等于原版“进入”。

这属于v1.34“剩余系统入口的原版流程校正”范围，必须补齐后才能验收。
