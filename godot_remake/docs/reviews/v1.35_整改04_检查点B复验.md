## 2. B-01：缺少warehouse恢复负向证明

检查点B要求每个检查点附一个对应负向失败。目前只有三处正向`assert_game_state_restored()`，没有故意破坏warehouse后证明比较器会报错的测试。

建议把差异计算暴露为可测试函数：

```gdscript
static func game_state_restore_differences(before: Dictionary) -> Array:
    return _compare_snapshots(before, snapshot_game_state())

static func assert_game_state_restored(before: Dictionary) -> void:
    var differences := game_state_restore_differences(before)
    assert(differences.is_empty(), "STATE_RESTORE_MISMATCH: " + str(differences))
```

在专项中增加真实GameState负向：

```gdscript
var before := Support.snapshot_game_state()
GameState.warehouse[0] = {"item_id": "NEGATIVE_WAREHOUSE_SENTINEL"}
var differences := Support.game_state_restore_differences(before)
assert(
    Support.has_error_code(differences, "VALUE_MISMATCH:warehouse"),
    "checkpoint B negative expected warehouse mismatch, got: " + str(differences)

Support.restore_game_state(before)
Support.assert_game_state_restored(before)
```

如果`has_error_code()`只支持冒号前的错误码，则将差异改为结构化错误，或增加检查完整字符串前缀的helper。不得只断言`not differences.is_empty()`。

## 3. B-02：当前比较不是严格deep equality

当前三个比较函数最终都使用：

```gdscript
str(before_value) == str(after_value)
```

这会把不同类型但文本相同的值判为相等，例如整数`1`与字符串`"1"`。因此当前实现不能完整支持报告所称的`TYPE_MISMATCH`和严格deep equality。

标量比较应先比较类型，再比较值：

```gdscript
if typeof(before_value) != typeof(after_value):
    # TYPE_MISMATCH
elif before_value != after_value:
    # VALUE_MISMATCH
```

`_dict_equal()`和`_array_equal()`递归到标量时也应采用相同规则。更推荐让递归比较器返回带完整路径的错误，例如：

```text
TYPE_MISMATCH:warehouse[0].count
VALUE_MISMATCH:warehouse[0].item_id
```

至少增加一个小型比较器负向：

```gdscript
before = {"warehouse": [{"count": 1}]}
after  = {"warehouse": [{"count": "1"}]}
```

必须得到`TYPE_MISMATCH`，不得判为相等。
