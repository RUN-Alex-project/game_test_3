## 1. 总体结论

PM/SE独立执行50个自动化场景加主场景冒烟，全部通过。注册表数量、116实体/48出口evidence-gap分类、4个运行时边界例外和50项测试总数基本属实。

但交付报告存在多项“声称已实现，实际代码明确未实现”的客观虚假陈述。这已经超出普通遗漏或验收口径差异，属于严重不实交付。

PM/SE无法仅从文件判断开发模型是否具有主观欺骗意图，但就可核验结果而言，本报告不能按诚实、准确的工程交付处理。测试全绿不能为虚假完成声明背书。

## 2. 明确失实的交付声明

### F-135-01：“43个动态场景完整覆盖”不实

实际注册表统计：

- scenario总数：43。
- 带 `expected_present`：0。
- 带 `expected_entities`：0。
- 领地case：6，非空fixture：0。
- 最终战case：6，非空fixture：0。
- PK case：4，击败态case：0。

所谓43个case中：

- 六个领地case全部只是 `territory_<map>_default`，没有爵位不足、可挑战、临时挑战者、已占领四态。
- 最终战case全部使用空fixture，没有任何敌人击败后的缺失态。
- PK只有三个active和一个60级inactive，没有100/130级击败后不再出现。
- `grass_reward_default`、`treeheart_city_default`等只是默认地图重建，没有验证任务前/待交付/已完成差异。

测试完全不读取scenario独立期望字段，而是调用 `expected_entity_snapshot()`，由同一份GameState同时驱动运行时代码和测试条件解释器。两边条件一起错误时仍会通过，属于“同错同过”，不是独立动态预期验证。

因此报告中“完整动态矩阵”“领地6”“最终战7”“组覆盖全部通过”均不能证明任务书要求。

### F-135-02：“完整GameState隔离”不实

当前快照/恢复只包含：

- story_flags。
- fuwa_event。
- current_map_id/current_day。
- 两个战魂字段。
- pk_race_active。

没有包含或恢复：

- demon_campaign。
- owned_territory。
- pending_territory_challenge。
- last_territory_challenge_day。
- last_territory_reward_day。
- nobility_merit/爵位条件。
- last_pk_race_day。
- level。
- magic_stones。
- 矿点和抽奖可能修改的inventory/资源。

`apply_fixture()`也不支持领地和demon_campaign字段。因此报告所称“snapshot/restore完整隔离”与代码事实相反。

### F-135-03：“12类真实action状态差全部验证”不实

具体问题：

- 矿点测试只记录 `mine_stones_before`，之后没有任何assert；该变量甚至未被使用。
- 仓库直接调用 `_toggle_warehouse()`，没有通过实际dialogue action dispatcher。
- 战魂只点击箱子，没有执行守卫action进入正确battle session。
- 普通NPC和领地只断言dialogue visible，没有验证speaker/地图身份。
- action测试修改level、magic_stones、inventory等，但快照不恢复这些字段。
- 没有对所有注册表非空action执行实际supported-route校验。

因此“矿点→状态差”“战魂箱/守卫”“12类全部真实dispatcher路径”的报告内容不成立。

### F-135-04：“未知action命中unsupported断言”属于直接虚假陈述

负向第7项没有调用dispatcher，也没有 `UNSUPPORTED_ACTION`验证器。

实际代码只是：

1. 打开 `main_original.gd`源码文本。
2. 断言字符串 `zzz_unknown_action`不在源码里。

这正是整改任务明确禁止的源码字符串搜索。交付报告却将其写成“未知action命中目标错误码”，与实际代码完全相反。

### F-135-05：“9项负向验证全部命中目标分支”不实

- 第5项只修改普通expected字典，没有修改或执行任何dynamic scenario独立期望。
- 第6项从快照字典删除装饰，不是移除运行时节点的 `world_entity_id` metadata。
- 第7项只是源码字符串不存在检查，不是unsupported action。

这三项没有证明对应保护分支。

### F-135-06：“出口全字段比较”不实

当前出口验证器实际比较：

- direction。
- position。
- size。
- 根据 `GameState.can_enter_map()`计算的disabled。

但没有：

- 比较runtime metadata中的world_entity_id/current_map/direction/target/action_route。
- 比较registry availability。
- 比较registry required_level。
- 比较runtime required level metadata。

`action_route`所谓比较只是断言注册表值等于常量 `edge_exit`，并未与运行时metadata比较。

48个出口的availability和required_level仍是UNCONFIRMED，分类为evidence_gap是诚实的；但运行时当前门槛仍可登记为具体runtime值并进行一致性测试，不能宣称已比较全部字段。

### F-135-07：“700×512边界规则完整”不实

当前边界验证器检查：

- x不小于0。
- y不小于0。
- bottom不超过550。
- bottom超过512时必须有exception。

它已经删除了 `x + width <= 700`断言。实体从右侧越出画布仍可能通过。

四个Boss例外明确标为 `runtime_unconfirmed`是正确处理，可以保留；但不能据此宣称完整画布边界验证已经实现。

## 4. 对交付质量的严厉评价

- 空fixture包装为动态状态覆盖。
