## 2. 阻断准入的问题

### QA-004：runtime活动来源保护分支永远不会执行

严重度：低  
置信度：高  
影响范围：注册表未来数据质量保护

`test_swf_evidence_registry_scene.gd` 定义的合法scope为：

```gdscript
const ALLOWED_SCOPES := ["runtime", "active+legacy", "legacy"]
```

注册表当前分布：

- `runtime`（字段缺省）：107项。
- `active+legacy`：1项。
- `legacy`：3项。

但source_refs活动来源检查使用：

```gdscript
if scope == "active" or scope == "active+legacy":
    assert(has_active_ref, ...)
```

`active`并不是合法scope，也没有任何条目使用该值。因此：

- `active+legacy`检查有效。
- 107个默认`runtime`资源不会进入这条活动来源断言。
- 当前数据人工审计仍为正确，但把一个runtime资源改成只指向legacy脚本时，专项测试可能继续通过。

这与整改01要求的“活动资源至少有一个非legacy来源ref”不一致。修复只需让判断使用现有schema中的`runtime`，不需要修改注册表内容或玩法代码。
