## 2. F-01：未知action没有证明资源和完整GameState不变

任务书第4节明确要求unknown action“不打开对话、不战斗、不改地图、不改资源”。当前neg7只直接断言对话、session、地图；其GameState快照在`Support.apply_fixture({})`之前取得：

```gdscript
var gs_n7 := Support.snapshot_game_state()
Support.apply_fixture({})
...
main._dispatch_world_action(...)
...
Support.restore_game_state(gs_n7)
Support.assert_game_state_restored(gs_n7)
```

最后的deep equality只证明`restore_game_state()`可以恢复旧快照。即使dispatcher偷偷修改金币、魔石、背包或仓库，这些修改也会在比较前被restore抹掉，测试仍然通过。

整改方法：

1. 保留一个进入neg7前的outer snapshot用于清理。
2. `apply_fixture()`和地图初始化完成后，再取得`before_dispatch`快照。
3. 调用unknown dispatcher后、任何restore之前，执行`game_state_restore_differences(before_dispatch)`并断言空列表；同时保留对话、session和地图的直接断言。
4. 最后才恢复outer snapshot并验证恢复。

这样会同时覆盖gold、magic_stones、inventory、warehouse及快照内所有字段。

## 3. F-02：多项负向缺少mutation_applied证明

任务书第10.5节要求负向统一采用“先证明变异发生，再证明同一验证器失败”。当前neg1/2/3/4/8/9直接修改后调用验证器，没有显式证明目标确实被找到并被修改。

整改要求：每项增加精确的变异前置与结果断言，例如：

- neg1：先断言目标ID同时存在于expected/actual，erase返回true，再调用验证器。
- neg2：先断言`ZZZ_FAKE`不存在，添加后断言存在。
- neg3：记录原kind，写入后断言已变为`ZZZ_WRONG`且不同于原值。
- neg4：记录原direction，写入后断言实际不同。
- neg8：用`exception_removed`布尔值证明实际删除了Boss例外。
- neg9：用`token_mutated`布尔值证明实际替换了目标token。

随后仍须精确断言既有错误码。此项不要求新增玩法代码。
