## 2. D-01：rank_low没有调用任务书指定的真实报名入口

任务书第3节要求 `begin_territory_challenge()` 返回 `rank_too_low`，第10.4节也要求“调真实报名入口”。当前测试只调用只读的 `territory_challenge_status(tmap)`。

整改要求：六图逐图调用 `GameState.begin_territory_challenge(tmap)`（或等价真实入口），断言 `success == false`、`reason == "rank_too_low"`、pending不变且无临时守卫。只读status可作为附加断言，不能代替报名入口。

## 3. D-02：challenger_active缺少战斗会话锁定断言

任务书明确要求 battle session 锁定正确 challenger ID。当前代码只检查临时演员，没有检查：

```gdscript
main.scene_battle_controller.is_active()
main.scene_battle_controller.active_monster_id == challenger_id
```

六图每图都必须执行这两项，并在状态结束时取消会话，避免向下一状态泄漏场景控制器状态。

## 4. D-03：owned没有验证报名官显示已占领

任务书要求 owned 状态下“报名官对话反映已占领状态”。当前代码在守卫消失后直接计数，没有打开报名官对话。

整改要求：调用真实报名官入口（如 `_open_actor_dialogue("territory:" + tmap)`），断言对话可见且 `body_label.text` 包含“你现在正是这里的保护者”。六图逐图验证。

## 5. D-04：状态隔离报告不实

报告称“每个状态前后都有 snapshot/restore + deep equality”，暗示状态已完整隔离；但测试在 challenger_active 和 owned 中修改 `GameState.player_current_hp = 550`，而 `snapshot_game_state()`/`restore_game_state()`没有该字段。`assert_game_state_restored()`因此根本无法发现HP泄漏。

这是报告与实现的明确不一致。整改要求：把 `player_current_hp` 成对加入快照与恢复，并增加一次HP变异负向，精确命中 `VALUE_MISMATCH:player_current_hp`。同时在每个挑战态结束时取消battle session并断言控制器不再active。

## 6. D-05：缺少检查点D对应的负向证明

任务书第10.8节要求每个检查点附一个对应负向失败。本次只有24次正向计数，没有证明缺少任一地图/状态时验证会失败。

整改要求：建立24个稳定case ID（`map_id:rank_low|rank_ok|challenger_active|owned`）的集合验证器；负向复制集合并删除一个case，精确断言 `TERRITORY_STATE_COVERAGE_MISSING`。正向与负向须使用同一验证器。
