## 1. 项目方向与总目标

### 1.1 产品定位

把当前项目扩展为一款完整的单机魔域式 ARPG：保留 1.03 的即时点击地图、幻兽、装备、战斗和城镇 UI 气质，同时吸收本地 2.3/2.4 版本中已经存在的任务、朋友、资源、城堡、挑战和幻兽养成思路。

这不是联网 MMO，也不是用随机数字伪造“在线玩家”。它是一个有固定人物、固定经济账本、固定排行、可追溯交易和可重复游玩的单机世界。

### 1.2 成功标准

第一阶段完整主线通关目标为 40 至 60 小时；完成主线后，领地、城堡、幻兽、固定冒险者、赛季排行、挑战副本和收藏目标可提供 100 小时以上的可选内容。

长时长必须来自新的决策、目标、地理区域和角色关系，不能来自把同一 Boss 的生命值、掉率或重复次数无止境放大。

### 1.3 不可破坏的已有边界

1. 保留现有 1.03 UI 框架、地图点击交互、背包、装备、幻兽、战斗和当前存档。
2. 不擅自重置用户已要求的金币、魔石、经验、军功、战魂、精炼等覆盖数值。
3. 金币和魔石已经不能承担唯一的长期成长门槛；新增长线内容必须使用独立且可追溯的资源、声望、凭证、战利品和次数限制。
4. 不联网、不调用服务端、不假装真的有其他人在线；所谓“玩家”均是本地固定 NPC 冒险者。
5. 不一次性导入 2.4 的全部地图、全部任务或十八次主将转世。每个开发包都必须可独立测试、可独立回滚、可独立验收。
6. 除非单独获批，不引入第二个可玩职业，也不立即改为三只幻兽同时参战。

## 3. 体验总循环

玩家的每一轮有效游玩应形成如下循环：

探索区域 → 接取主线/委托/挑战 → 战斗与收集 → 获得战利品、声望、资源或关系进展 → 装备/幻兽/技能/产业成长 → 解锁新地图、新 NPC、新挑战和新交易机会。

为避免单纯刷怪，至少同时提供四条可选推进线：

| 推进线 | 核心目标 | 主要产出 |
|---|---|---|
| 战役线 | 推进大陆反攻和最终图腾 | 地图解锁、剧情 Boss、战役印记 |
| 冒险者线 | 与固定 NPC 建立关系、完成委托和竞争 | 友谊值、专属任务、邮件、排名情报 |
| 产业线 | 获取资源、购置产业、建设城堡 | 资源、设施等级、长期被动产出 |
| 构筑线 | 装备、技能、幻兽、元素与战魂培养 | 战斗力和打法变化 |

金币和魔石可作为日常便利货币，但不能独占稀有物品购买资格。稀有成长必须要求至少一种不可由现有无限商店直接取得的条件，例如战役印记、友谊信物、商会信誉、领地贡献、Boss 战利品或周挑战次数。

当前已有的救国王、魔军阵地、能源塔内容定义为序章与第一章，不推倒重写。之后按以下结构扩展。

### 4.2 地图扩展策略

不一次性做 79 张地图。首个世界扩展目标为新增 18 至 24 张地图，先保证路线、任务和交互密度，再考虑补全更多变体。

1. 地图 ID、显示名、背景资源路径、画布尺寸。
2. 入口、出口、方向、目标地图、等级/剧情可用条件。
3. 固定 NPC、怪物、采集物、装饰物的唯一 ID、资源、坐标、尺寸、交互 action。
4. 关联任务、首次进入文本、Boss/事件条件。

6. 运行时双向审计：注册表没有的演员不能悄悄出现；运行时声明的演员不能漏登记。

### 4.3 主线原则

1. 每章至少有一个“非击杀”目标，例如护送、调查、守城、交涉、资源修复或选择站队。
2. 每章结尾 Boss 至少有一个独特机制，例如援军、地形、护盾、限时目标、召唤物或阶段转换。
3. 绝不把“主将二世到十八世”按同一数值重复。最多设计五个有机制差异的轮回残影；其余可作为终局可选讨伐。
4. 每章至少让两名固定冒险者参与，使 NPC 关系线与战役线交叉。

### 5.3 关系机制

本地版本可借鉴的关系阶段为：认识、朋友、知己、恋人、爱人，对应阈值可先保留为 0、10、200、500、1000、2000。单机扩展中，恋爱内容必须可选且不影响主线通关；不得加入“分手即游戏失败”。

关系值来源：

| 行为 | 关系变化 | 限制 |
|---|---:|---|
| 正确完成个人委托 | +5 至 +40 | 每日或每周次数限制 |
| 赠送偏好礼物 | +1 至 +20 | 每日上限，防止单一物品刷满 |
| 邮寄急需物品 | +3 至 +15 | 需真实物品转移 |
| 擂台切磋 | 胜负不同 | 每日上限，失败不扣装备 |
| 共同战役节点 | +10 至 +50 | 仅首次剧情 |
| 违约、恶意取消交易 | -5 至 -30 | 有明确可见原因 |

关系每一步必须记录来源事件、游戏日、对象、数值变化和原因文本，便于存档审计、测试与玩家查看。

### 5.4 日程和成长

NPC 采用“日结模拟”而非在后台每帧真实跑地图。每个游戏日结算一次：

1. 根据性格、等级、章节和资源选择一个行动：挖矿、狩猎、训练、交易、休整、发布委托、参加擂台。
2. 产生受约束的收益和消耗，写入 NPC 自己的账本。
3. 更新装备、幻兽、排名候选分数和消息。
4. 若有与玩家相关的结果，投递到邮件或公告板。

所有随机结果必须由持久化种子、游戏日和 NPC ID 得出；读档后同一天不可重复刷出不同结果。

### 5.5 委托、邮件和直接交易

首批功能：

1. 好友委托：收集、击杀、护送、探查、制作、借用幻兽六类。
2. 邮件：NPC 可给玩家寄奖励、报价、邀请和战报；玩家可邮寄物品给 NPC。
3. 直接交易：仅交易各自账本中真实拥有的物品；确认后物品和货币必须原子转移。
4. 关系奖励：特殊对话、专属任务、战役援助、幻兽建议、排行榜情报。

NPC 不能无限送钱、无限送极品、无限收购。任何赠与与交易都必须有来源、库存和冷却。

## 6. 排行榜、擂台与单机 PvP

### 6.1 排行榜

榜单不是预先写死的文本。每个榜项都必须由玩家和固定冒险者的实际持久数据计算。

首批榜单：

| 榜单 | 排序主值 | 并列规则 | 更新时机 |
|---|---|---|---|
| 战斗力榜 | 实际战斗力 | 等级、战役进度、ID | 日结和装备变化 |
| 幻兽榜 | 最高幻兽总评分 | 星级、品质、ID | 幻兽变化 |
| 擂台榜 | 赛季积分 | 胜率、累计胜场、ID | 对局结算 |
| 探索榜 | 已发现地图和秘密点 | 主线进度、ID | 地图发现 |
| 商会榜 | 商会信誉 | 正常成交数、履约率、ID | 交易/拍卖结算 |
| 领地榜 | 领地贡献 | 守卫次数、资源贡献、ID | 每周结算 |

排名变化必须有原因文本，例如“雷恩因击败冰封骑士长上升两名”，不得只显示数字跳动。

### 6.2 异步单机 PvP

1. 对手是固定冒险者的属性、装备、幻兽和技能快照。
2. 对战使用现有战斗控制器，不访问网络。
3. 每日提供练习赛、挑战赛和赛季赛三类；练习赛无排名损失。
4. 失败不夺取真实装备、不删除幻兽、不破坏主线。
5. 胜利产出擂台印记、排名分和对手关系变化，而不是大量金币/魔石。
6. NPC 之间的比赛可通过日结模拟生成摘要和结果，不必后台真的执行几百场完整战斗。

### 6.3 赛季

一个赛季等于 14 个游戏日。赛季结束结算榜单，保留历史名次，发放称号、装饰、专属材料或商会信誉。不得清空玩家核心装备、等级和幻兽。

## 7. 单机交易所与拍卖行

### 7.1 定位

拍卖行是单机扩展设计，不宣称源自原版。它的目标是让固定冒险者、战利品、资源和玩家构筑发生关联，而不是提供另一个无限金钱按钮。

### 7.2 货币与防通胀

由于玩家可能拥有极高甚至超上限的金币、魔石，稀有拍卖不能只用金币竞价。

新增两种可审计货币：

| 名称 | 来源 | 用途 | 是否可无限购买 |
|---|---|---|---|
| 商会信誉 | 正常交易、履约、任务、赛季结算 | 高级拍卖资格、稀有委托 | 否 |
| 竞拍凭证 | 周挑战、领地、防线任务、少量 NPC 委托 | 稀有物品竞价、保留出价 | 否 |

金币与魔石仍可用于普通商品和快捷服务，但不替代上述门槛。

### 7.3 上架与成交规则

1. 所有物品都必须有来源：怪物掉落、任务、采集、NPC 账本、玩家背包或系统明确发放。
2. 每个拍卖条目有唯一 listing_id、卖家、物品、数量、底价、一口价、开拍日、结束日和出价记录。
3. 玩家出价时，凭证和可退回货币进入托管；竞价失败或流拍自动退回。
4. NPC 竞价必须受预算、物品需求、性格、已有装备和信誉影响，不能凭空无限抬价。
5. 结算必须原子执行：卖方获得对价、买方获得物品、条目关闭、失败时无一方丢失物品。
6. 每日最多出现六个普通条目和两个稀有条目；每周一个主题拍卖。
7. 所有交易与竞价要在“商会账本”中可查看和测试。

### 7.4 直接交易防滥用

1. NPC 不收购绑定、任务、无来源或不可交易物品。
2. 同一天向同一 NPC 重复倒卖同一类物品时，收购价递减并显示原因。
3. 交易失败不得扣物品或货币。
4. 交易与拍卖同用物品来源和原子转移服务，面板不得直接改背包数组。

## 8. 资源、产业、声望与城堡

### 8.1 新增长线资源

| 资源 | 主要来源 | 主要用途 |
|---|---|---|
| 大陆资源 | 采集、战役、产业、领地任务 | 城堡、设施、公共建设 |
| 声望 | 首领、探索、守城、剧情选择 | 区域准入、产业与城堡资格 |
| 战役印记 | 章节 Boss、战役目标 | 高级装备/幻兽成长 |
| 领地贡献 | 守卫、修复、防线任务 | 领地设施、周结算 |
| 商会信誉 | 正常交易、拍卖履约、委托 | 市场权限 |
| 友谊信物 | 固定冒险者任务、关系节点 | 关系专属物品和剧情 |

### 8.2 产业与城堡路线

借鉴本地版本的资源、产业、城堡和设施升级思路，设计为：

1. 玩家先通过树心/南城战役获得第一处“补给据点”。
2. 声望和大陆资源达到条件后可购买产业：矿场、药圃、港口货栈、幻兽牧场。
3. 产业每天产出有限资源，并有维护、事件与升级选择。
4. 城堡不是单纯数值建筑，而是解锁设施、任务、赛季公告和 NPC 聚会。
5. 城堡设施包括生命之源、魔力源泉、战术大厅、幻兽温室、商会档案室。
6. 所有被动产出在每日结算一次，且有明确来源、上限和日志。

### 8.3 领地

保留现有六处领地玩法，并扩展为三类状态：

1. 未解锁：受剧情、等级或声望限制。
2. 争夺中：可挑战守卫，固定 NPC 会竞争或协助。
3. 已占领：每日提供有限资源、每周触发防守或建设任务。

领地不应成为挂机无限产出器。产出上限、维护、事件和周任务必须让玩家做出选择。

## 9. 战斗、技能、怪物与挑战

### 9.1 技能扩展原则

当前角色保留现有技能。后续优先增加“技能分支”和“战斗风格”，而不是立刻加入第二个完整可玩职业。

可借鉴的战士风格技能：斩魂、旋风斩、刀光斩、飞天连斩、狂暴。  
可借鉴的法术风格技能可先作为 NPC/Boss 技能：火球术、电击术、爆雷术、雷霆万钧。

每个新增技能必须有：

1. 明确的解锁任务或材料。
2. 冷却、消耗、目标规则和数值来源。
3. 至少一个与现有技能不同的战术用途。
4. 战斗、打断、死亡、切图和存档恢复测试。

### 9.2 挑战线

建议按等级和玩法分为九条，吸收本地版本的任务名和方向：

| 挑战 | 等级段 | 机制 | 长线奖励 |
|---|---|---|---|
| 黑骑士试炼 | 30–39 | 首次精英单挑 | 战役印记 |
| 军团管理员 | 40–49 | 多波敌人 | 军功、关系任务 |
| 守城演习 | 50–59 | 四方向防守 | 领地贡献 |
| 守卫沼泽 | 60–69 | 限时守点 | 沼泽声望 |
| 黑衣圣兽师 | 70–79 | 幻兽强化敌人 | 幻兽材料 |
| 偷袭后路 | 80–89 | 潜入/优先目标 | 商会凭证 |
| 冰封谷试炼 | 90–99 | 元素抗性与阶段 Boss | 元素材料 |
| 断舰行动 | 100–109 | 多目标战役 | 城堡资源 |
| 大魔王挑战 | 110+ | 周挑战、多阶段 | 终局收藏与榜单 |

### 9.3 Boss 设计要求

每个章节 Boss 需登记：

1. 阶段、技能序列、召唤物、弱点或战场规则。
2. 奖励表与唯一掉落来源。
3. 重复挑战规则、次数限制和排行榜是否计入。
4. 失败状态，不得让失败卡死任务或丢失不可恢复物品。
5. 固定 NPC 是否能提供战前情报、助战或挑战竞争。

## 10. 幻兽、装备与收藏终局

### 10.1 幻兽发展路线

1. 保持现有双幻兽出征和 HUD 框架。
2. 新增“援护幻兽”槽位作为第三只幻兽的前置体验：只提供有限被动，不占现有双幻兽战斗 UI。
3. 通过“圣兽合体”长任务解锁援护槽位；后续是否改成真正三宠同场，必须另立 UI 与平衡任务书。
4. 加入二代幻兽、内丹、炼狱、兽王等中后期内容，但每种机制都要有独立数据和测试，不要把所有成长公式塞到 GameState。

### 10.2 幻兽炼狱与兽王

1. 幻兽炼狱为每周挑战：连续击败三种强化魔幻兽，每轮机制不同。
2. 挑战失败可重新尝试，但当周奖励次数受限。
3. 兽王挑战用于掉落稀有幻兽材料、竞拍凭证或战役印记。
4. 幻兽奖励优先提供构筑选择而不是无条件战斗力暴涨。

### 10.3 装备与材料

可引入的内容：

| 内容 | 作用 | 约束 |
|---|---|---|
| 玄铁矿 | 为装备增加附加效果 | 有明确消耗和装备条件 |
| 陨铁矿 | 激活装备战魂/特殊效果 | 不覆盖当前战魂用户规则 |
| 元素装备 | 风火水地雷五系侧向构筑 | 先从 Boss/挑战掉落开始 |
| 雷兽追踪 | 引导至元素装备首领 | 不是纯随机刷点 |
| 宝石融合 | 两颗高阶宝石合成混合圣石 | 记录输入、输出、成功结果 |
| 收藏图鉴 | 记录装备、幻兽、Boss 与故事 | 只记录已真实获得内容 |

所有新增材料必须登记：来源、可交易性、堆叠上限、消耗入口、回收规则、存档字段和测试。

## 11. 任务网络设计

### 11.1 目标规模

最终精选任务目标为 60 至 75 条，不要求全搬本地 80 条。组成建议：

| 类别 | 数量目标 | 说明 |
|---|---:|---|
| 主线章节任务 | 24 | 推进世界、地图与终局 |
| 区域支线 | 16 | 补充人物、产业和地图秘密 |
| 冒险者专属任务 | 12 | 与首批 12 NPC 一一对应 |
| 分段挑战 | 9 | 见第 9 章 |
| 日常/周常 | 12 | 精选轮换，不强迫全做 |
| 隐藏收藏任务 | 6 | 探索、图鉴、信件和地图秘密 |

同一任务可服务多条系统线，但不得只换怪物名和数字。

### 11.2 日常与周常设计

借鉴本地版本的初/中/高级军功、功勋、悬赏、好友委托、紫水晶、荣誉、幻兽炼狱、挑战兽王方向。

规则：

1. 每日最多出现三项日常、每周最多两项高价值挑战，避免清单过载。
2. 任务池随章节、等级、NPC 关系和地图解锁扩展。
3. 金币和魔石不是核心奖励；核心奖励为材料、信誉、声望、印记或关系。
4. 失败、放弃、跨日和读档均须有明确规则。
5. 日常随机要由存档种子确定，不能通过反复读档重抽。

### 11.3 任务数据结构

每条任务至少需要：

1. task_id、类型、章节、前置、推荐等级、地图范围。
2. 目标列表、目标状态、失败条件、跨日策略、可重复策略。
3. 奖励列表、来源标签、是否影响关系/声望/产业。
4. 发放 NPC、对话 key、完成 NPC、未完成提示。
5. 证据或原创设计分类。
6. 存档字段、迁移默认值、测试场景 ID。

任务面板不得将任务逻辑硬编码在 UI 按钮回调中。

world_seed + game_day + system_id + entity_id + event_sequence

推导。系统不得使用不可保存、不可复现的全局随机状态作为关键奖励依据。

## 14. 分包实施路线与验收门槛

以下为开发包，不等同于自动发布版本。上一个包正式验收前，不进入下一个包的生产开发。

### 包 A：2.x 内容注册表与扩展基础

目标：建立可靠的“可借鉴内容目录”，不改变玩法。

验收：

1. 证据 token 可定位到本地反查文本。

### 包 B：固定冒险者基础与关系系统

目标：完成 12 名固定冒险者、关系、日结、委托和邮件，不做拍卖。

执行内容：

验收：

1. 每名 NPC 的日结结果可由种子重现。
2. 赠礼、委托、邮件均有真实状态差和幂等保护。
3. NPC 物品、货币、关系无凭空增减。
4. 旧存档加载后 NPC 字段采用固定默认值。
5. UI 启动隐藏、边界、关闭和文本裁剪测试通过。

### 包 C：排行榜、异步擂台与战报

目标：让固定冒险者成为可感知的竞争对象。

执行内容：

1. 新增 RankingService 和六类榜单。
2. 实现练习赛、挑战赛、赛季赛和战报。
3. 使用角色快照参与异步单机 PvP。
4. 每日结算 NPC 对战摘要，禁止后台模拟大量完整物理战斗。

验收：

1. 排名完全由实际持久化数据导出。
2. 同分规则稳定、读档一致。
3. 失败不丢失装备、幻兽、关键剧情物品。
4. 赛季结算只执行一次，重入/读档不重复奖励。

### 包 D：资源、产业、城堡与领地扩展

目标：建立长期经营目标，并让现有六领地有持续意义。

执行内容：

1. 实现大陆资源、声望、战役印记、领地贡献和商会信誉。
2. 实现补给据点、四类产业、城堡和五类设施。
3. 把现有领地接入防守、建设和周结算。
4. NPC 可参与产业、委托和领地事件，但不得抢走玩家的主线成果。

验收：

1. 每种资源都有来源、去向、上限和账本。
2. 日结可重现，不重复产出。
3. 设施升级失败、资源不足、跨日、读档和坏档均有测试。
4. 金币/魔石无限不会绕过声望、贡献、信誉和战役印记条件。

### 包 E：地图与大陆反攻战役

目标：新增第一批 18 至 24 张地图和第二至第六章主线骨架。

执行内容：

1. 每个区域先完成一条完整可玩路线，再加入下一区域。
2. 建议顺序：树心前线 → 南城防线 → 冰封路线 → 黑渊区域。
3. 每章至少三项主线目标、一条区域支线、一个关键 Boss、一个固定 NPC 剧情节点。
4. 完成地图出口、演员、任务条件、战斗和存档审计。

验收：

1. 地图注册表和运行时双向精确比较。
2. 所有出口可达或显示具体锁定原因。
3. 主线可从当前已有终点连续进入，不依赖手动改存档终态。
4. 新区域切图、战斗中断、任务失败、读档和返回城镇全覆盖。

### 包 F：商会、直接交易与拍卖会

目标：建立封闭、可追溯、不会因无限金币崩坏的单机市场。

执行内容：

1. 实现 ItemProvenanceService、MarketService、AuctionService。
2. 先做 NPC 直接交易和邮寄物品，再做普通拍卖，最后做主题拍卖。
3. 实现商会信誉、竞拍凭证、托管、竞价、流拍和结算账本。
4. 固定 NPC 的预算、需求、库存和竞价策略必须数据驱动。

验收：

1. 每件成交物品的来源和去向可追踪。
2. 出价、撤回、流拍、成交、重复结算、读档重入均原子且幂等。
3. NPC 不会无限生成货币或物品。
4. 竞拍不能只靠金币/魔石无限压价。
5. 至少 12 个负向测试：重复点击、库存不足、对价不足、重复结算、错误卖家、错误物品来源等。

### 包 G：分段挑战、技能分支、元素与装备

目标：把战斗从单纯堆数值升级为多种策略。

执行内容：

1. 实现九条分段挑战线。
2. 实现第一批技能分支和 Boss 机制。
3. 实现玄铁、陨铁、元素装备、雷兽追踪、宝石融合的最小闭环。
4. 所有新材料先只服务少量清晰功能，避免系统爆炸。

验收：

1. 每个挑战有独特机制和失败恢复。
2. 技能数据、冷却、取消、死亡、切图均自动化测试。
3. 装备材料输入输出一致，失败不会吞物。
4. 不改变用户已签署的精炼、战魂和经验覆盖规则。

### 包 H：幻兽炼狱、兽王、二代幻兽与收藏

目标：提供终局幻兽深度与收藏动机。

执行内容：

1. 实现援护幻兽槽位和圣兽合体长任务。
2. 实现幻兽炼狱、兽王挑战、二代幻兽、内丹和收藏图鉴。
3. 把幻兽、装备、地图、Boss、信件纳入收藏。

验收：

1. 双幻兽出征仍保持兼容；援护槽不破坏顶部 HUD。
2. 幻兽生成、成长、合成、失败、读档和背包满全覆盖。
3. 不上线真正第三宠同场，除非单独完成 HUD、战斗和数值评审。

### 包 I：剧情后日谈、赛季、事件与发布收口

目标：让通关后的世界持续运作，并完成正式试玩前质量门禁。

执行内容：

1. 建立 14 日赛季、后日谈任务、城堡事件、排行榜历史和主题拍卖。
2. 增加探索秘密、图鉴、称号、NPC 后续剧情。
3. 进行全量存档迁移、长期日结、赛季结算、泄漏和发布包验证。

验收：

1. 连续至少 30 个游戏日的确定性模拟可重复。
2. 赛季、拍卖、日结不会在读档后双结算。
3. 完成主线后仍可正常进入所有长期系统。
4. 更新 README、攻略、版本改动、数据字典和存档说明。

## 15. 测试与交付规范

### 15.1 每个开发包最低测试要求

1. 数据 schema 测试。
2. 核心服务正向测试与至少六个真实变异负向测试。
3. 存档：旧档加载、缺字段默认、坏档拒绝、加载失败内存不变。
4. 相邻系统回归：地图、战斗、背包、幻兽、任务、UI。
5. 全量测试与主场景冒烟。
6. 如有发布包变更，重建 PCK/EXE、manifest、SHA256SUMS、发布门禁。

### 15.2 禁止的“假测试”

1. 不得只检查函数存在、字符串存在或源码包含某个 token。
2. 不得在测试中直接写入本应由生产流程产生的终态，再宣称已验证流程。
3. 不得用测试辅助函数替代生产 dispatcher。
4. 不得用截图、人工目测或“看起来正常”作为唯一 UI 验收。
5. 不得只断言错误列表非空；负向测试必须命中预期错误码，重要场景应断言错误集合精确相等。
6. 不得因为测试通过就声称本地版本机制已经被证实；证据状态必须独立登记。

### 15.3 开发交付报告格式

每个开发包完成后，开发工程师必须按如下格式提交：

1. 结果摘要：做成什么、未做什么。
2. 修改/新增/删除文件绝对路径。
3. 数据模型与存档影响。
4. 生产调用链和关键状态差。
5. 本地版本证据、原创设计与 evidence_gap 的明确区分。
6. 正向、负向、相邻、全量测试命令和实际输出。
7. 已知限制、未关闭问题和建议的下一包。
8. 明确声明：没有使用截图识别作为验收依据。

PM/SE 不会只依据报告签署；必须独立阅读代码、注册表、测试和关键运行日志。

## 16. Luna Max 执行分工

### 16.1 必须委派给 Luna Max 子代理的大体量任务

1. 2.3/2.4 全量文本、任务、地图、物品、NPC 与技能反查。
2. 数十张地图的注册表录入、出口矩阵和实体审计。

4. 12 至 24 名固定冒险者的资料、日程、委托池和台词初稿。
5. 大规模数据 schema、存档迁移矩阵、回归测试和负向测试矩阵。
6. 发布包重建、哈希核验、文档一致性扫描和长期模拟。

### 16.2 Codex 的职责

1. 确定范围、优先级、系统边界和产品决策。
2. 编写任务书、审查设计、定义验收标准。
3. 审查 Luna Max 的提交是否存在自证、漏测、越界或不实表述。
4. 进行关键抽样复验、风险判断和版本签署。
5. 不亲自承担大规模实现、批量迁移或长时间反查。

### 16.3 子代理任务拆分原则

每次交给 Luna Max 的任务必须是边界清晰、输入输出可检查的子任务。例如：

1. “从 2.4 导出文本中整理任务条目和证据 token，输出 JSON，不改 Godot 代码。”
2. “实现 AdventurerService 与 12 人数据，不实现拍卖。”
3. “仅实现拍卖托管和结算，禁止更改现有背包拖放逻辑。”
4. “只写 30 日日结确定性测试和坏档测试，不修改生产逻辑。”

禁止把“把整个扩展做完”作为一次性子代理任务。

## 18. 需要用户后续确认的产品选择

以下选择不会阻碍包 A，但在对应开发包开始前必须由用户或 PM/SE明确确认：

1. 是否允许玩家与固定 NPC 发展恋爱关系，还是只保留朋友/知己。
2. 拍卖行是否允许玩家上架自己的稀有物品，还是先仅允许购买 NPC 上架物。
3. 是否未来开放真正第三只幻兽同场，还是永久使用双出战加援护槽。
4. 是否让现有角色学习法术风格技能，还是仅让 NPC/Boss 使用法术。
5. 城堡是否做成可进入的独立地图，还是先做成管理面板。
6. 终局是否采用多结局，还是单一结局加后日谈。

在未明确前，默认方案为：无强制恋爱、玩家可上架但有严格来源审计、双出战加援护槽、法术先供 NPC/Boss、城堡先管理面板、单一结局加丰富后日谈。
