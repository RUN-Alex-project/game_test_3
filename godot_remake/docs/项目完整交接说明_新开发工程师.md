## 1. 项目是什么

本项目是《魔域 1.03》Flash 单机小游戏的 Godot 4 重制工程。目标不是把 SWF 自动转换成 Godot，也不是做联网 MMO，而是在保留原版主要画面、地图、角色、流程和氛围的基础上，做一款可长期扩展的单机游戏。

核心产品方向：

1. 保留 1.03 原版主城、地图、NPC、战斗、装备、幻兽、任务和主要剧情。
2. 所有新内容必须是单机内容，不依赖服务器、真实玩家、实时匹配或联网经济。
3. 后续允许加入“像玩家一样生活的固定 NPC”：固定冒险者、关系、邮件、交易、拍卖、异步擂台、排行榜、领地经营和赛季。
4. 借鉴本地 `E:\魔域\2.2.swf`、`2.3.swf`、`2.4.swf` 时，必须区分：本地版本明确证据、局部证据、本项目原创单机扩展和证据缺口。
5. 原版证据、Godot 当前运行值和用户主动修改的数值必须分层记录，不能混成“原版就是这样”。

本项目目前不是逐像素完全还原。部分 UI、演员位置、动态效果和时间线仍保留 `evidence_gap`。不能因为游戏能运行就宣称原版完全复刻。

## 2. 用户明确要求与不可违背的产品决定

### 2.1 单机原则

1. 不做真实多人。
2. 不做服务器、实时玩家、聊天室、公会在线系统或网络拍卖。
3. 所谓“其他玩家”只能是固定、本地、可持久化的 NPC 冒险者。
4. PVP 只能做离线异步对战：对手由固定 NPC 的属性、装备、幻兽和技能快照构成。
5. 排行榜只计算玩家和固定 NPC 的本地持久状态，不伪装为全球在线排行。
6. 拍卖行为封闭的单机经济模拟，NPC 出价必须有预算、偏好、关系和确定性种子。

### 2.2 开发输入原则

正式开发工程师使用纯文本上下文工作。任务输入和验收证据只能使用：

- 源代码与差异；
- JSON、TSV、CSV 和 Markdown；
- 本地资源路径、资源 ID、节点属性；
- Control/global_rect、位置、尺寸、层级等运行时数据；
- 命令、退出码、日志、PASS 标记和错误码；
- 自动化测试和确定性状态差。

不要请求截图、图片识别、屏幕录制或视觉附件。需要视觉判断时，由 PM/SE 另行进行独立视觉 QA，视觉结论不能替代开发侧的代码和测试证据。

### 2.3 发布顺序

1. 一次只开发一个版本。
2. 前一版本未正式签署，不得启动下一版本。
3. 开发报告不是验收结论；PM/SE 必须独立复验代码、数据、测试、存档和证据。
4. 生产代码或资源变动后，发布包必须按顺序重建：源码定稿 → PCK/EXE → manifest → 最后生成 SHA256SUMS → doc gate → release gate。

## 6. 当前玩法系统

### 6.1 战斗

1. 战斗发生在当前地图演员上，不打开旧的专门战斗面板。
2. 战斗使用 BattleSession、SceneBattleController、CombatService 和 FeedbackService。
3. 支持人物普通攻击、主动技能、普通怪攻击、Boss 攻击、受击、闪避、死亡、复活和掉落。
4. 时间线有生产调度器和取消策略；切图/取消后必须恢复节点状态并释放 Scheduler/Tween/Timer。
5. 旧 session 回调不得结束或污染新 session。
6. 战斗反馈有事件顺序、去重、operation_id 和状态矩阵。

### 6.2 装备与强化

装备槽：武器、头盔、项链、衣服、手镯、战靴。

强化域：

- 品质；
- 魔魂；
- 战魂；
- 天魂；
- 地魂；
- 洞数/装备实例属性。

材料不足、已激活、等级上限等失败路径不得扣料。每次真实尝试只扣一次材料。

### 6.3 幻兽与研究所

1. 当前有 6 个幻兽模板。
2. 幻兽最高 50 级。
3. 最多同时出征 2 只。
4. 幻兽经验、升级、召回、出征、合体、解体、幻化和经验球训练均已存在。
5. 研究所有技术等级、日产量、库存、资助、产量任务和购买幻兽。
6. 经验球容量为 27,000，主要用于幻兽相关流程，不是人物直接升级按钮。

### 6.4 经济、背包与商店

1. 杂货商、收藏家有买入/出售入口。
2. 银矿、金矿和矿石品质影响交易结果。
3. 用户要求的超大金币/魔石采用 int64 范围处理；达到 int64 上限前必须明确拒绝，不可溢出回负数。
4. 拖动失败、背包满、仓库满不能让物品消失。

### 6.5 时间、军衔、爵位与关系

1. 游戏从第 1 天开始，每天有有限时间槽。
2. 日常任务、研究所、PK、军饷、公主礼物和部分剧情读取星期/日期。
3. 军功决定军衔；功勋决定爵位；爵位参与部分地图/领地资格和战斗力。
4. 玫瑰提升公主好感；关系状态有每日/周日/重复领取限制。

## 11. 测试和门禁

### 11.1 当前唯一测试清单

`tests/test_manifest.json` 是平台中立唯一清单，当前 66 个自动化场景。`run_tests.ps1` 和 `run_tests.sh` 是 `tools/run_tests.py` 的薄入口。

Windows 全量：

```powershell
cd E:\deepseek-work\TKS3_mod\godot_remake
.\run_tests.ps1
```

Linux/WSL：

```bash
cd ~/deepseek-work/TKS3_mod/godot_remake
export GODOT_BIN=/usr/local/bin/godot
./run_tests.sh
```

runner 失败条件包括：

1. 非零退出码；
2. `SCRIPT ERROR:`；
3. 未排除的 `ERROR:`；
4. `FAILED`、Assertion failed；
5. `ObjectDB instances leaked`；
6. 自动化场景缺少 `^PASS ` 完成标记；
7. 非允许的 SKIP/不可写路径等绕过。

主场景冒烟不要求 PASS 行，但要求退出码、错误、泄漏和启动路径正常。

### 11.2 文档门禁

```powershell
python .\docs\doc_gate.py
```

当前数量从 `tests/test_manifest.json` 机械读取，并与 `docs/current_test_baseline.json` 和当前状态文档交叉核对。不要重新引入硬编码 65。

### 11.3 发布门禁

```powershell
.\work\run_release_gate.ps1
```

门禁包含：文档、三方哈希、自然退出、APP_READY、错误日志、早退、超时、清理和真实负向变异。

### 11.4 测试写法原则

1. 测试走真实生产入口，不直接修改成功终态。
2. 成功断言必须检查实际状态差。
3. 失败断言必须检查所有关键状态不变。
4. 负向先证明变异生效，再调用正向同一验证器，命中精确错误码。
5. 不能用源码搜索代替 dispatcher、状态机或运行时验证。
6. 不能用测试自己推导出的期望去验证同一算法；需要独立固定 oracle 或登记期望。
7. 测试结束必须释放场景、timer、tween、scheduler 和临时文件。

## 17. 交付报告固定格式

以后每次开发交付必须包含：
