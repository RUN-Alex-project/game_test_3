## 一、P0-1 存档事务与崩溃恢复

### 已完成

save_game 重写为**可恢复事务式保存**（非原子替换）：
- **恢复状态机**（5 种状态）：
  1. 正式档有效 → 清理 .tmp/.bak → 正常保存
  2. 正式档缺失 + .bak 有效 → 恢复 .bak → 正常保存
  3. 正式档损坏 + .bak 有效 → 恢复 .bak → 正常保存
  4. .tmp 有效 + 正式档缺失 → 提交 .tmp → 正常保存
  5. 三档都损坏 → 返回 false 禁止覆盖
- **每个操作检查返回值**：rename/remove/open/write/flush/read/restore
- **cleanup_fail 返回 false**（不无条件返回成功）
- **stale 文件清理**：恢复状态机根据有效性决定清理/恢复，不盲删 .bak
- **6 故障注入点**：tmp_open_fail / write_fail / verify_fail / backup_fail / replace_fail / cleanup_fail
- **flush() 显式调用**：tmp_file.flush() 后 close()
- **读回完整 schema 校验 + 文本深比较**：38 键 + 类型检查 + verify_text == json_str

文件：`scripts/game_state.gd` save_game() / _recover_save_state() / _is_save_file_valid()
