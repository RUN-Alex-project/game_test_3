4. 未来地图、任务、NPC、物品和技能如何使用稳定 ID，而不与现有 1.03 数据冲突。

## 5. 注册表字段合同

每项内容至少包含：

~~~json
{
  "id": "stable_ascii_id",
  "kind": "map|quest|npc|item|skill|boss|system",
  "display_name": "中文名",
  "source_version": "2.2|2.3|2.4|project",
  "evidence_source": "相对文本路径或 null",
  "evidence_tokens": ["精确可搜索 token"],
  "evidence_status": "local_version_confirmed|local_version_partial|singleplayer_extension|evidence_gap",
  "planned_version": "v1.43|...|not_planned",
  "design_status": "borrowed|adapted|singleplayer_extension|not_selected",
  "dependencies": [],
  "notes": ""
}
~~~

规则：

1. ID 为稳定 ASCII，不能依赖数组位置或显示名。
2. evidence_source 必须在 docs/evidence 或受控的 work/v142 文本目录内；不得直接指向原始 SWF。
3. local_version_confirmed 至少一个 token 在来源中精确命中。
4. evidence_gap 和 singleplayer_extension 不允许伪造 source/token。
5. planned_version 必须是本任务书路线中的版本，或 not_planned。
6. 候选地图和现有 28 个地图 ID 不能冲突。
7. 候选任务和现有 3 个任务 ID 不能冲突。

## 6. 测试与文档门禁

### 6.1 注册表正向测试

专项必须检查：

1. JSON 可解析。
2. ID 全局唯一。
3. kind、source_version、evidence_status、planned_version、design_status 都来自允许集合。
4. local_version_confirmed 的每个来源文件存在且 token 精确命中。
5. evidence_gap/singleplayer_extension 不允许伪造来源 token。
6. 候选地图不少于 18，任务数 60–75，首批 NPC 为 12，候补 NPC 至少 24。
7. v22 数据合同字段 ID 唯一、默认值与类型相符、服务归属非空。
8. 现有 maps.json 与 quests.json 的 ID 不与候选目录冲突。

### 6.2 真实变异负向

至少八项，且每项先断言变异已生效，再调用正向同一验证器，命中精确错误码：

1. 将 confirmed token 改为不存在 token。
2. 将 confirmed source 改为不存在文件。
3. 复制一个已有 ID。
4. 将 evidence_status 改为非法值。
5. 将 source_version 改为不允许值。
6. 将 planned_version 改为不存在版本。
7. 删除 v22 必填字段。
8. 将候选地图 ID 改为当前 maps.json 中已有 ID。
9. 将候选任务 ID 改为当前 quests.json 中已有 ID。
10. 将 singleplayer_extension 非法加上原版证据 token。

### 6.3 测试数量门禁

新增专项场景必须加入 run_tests.ps1。由于场景数会从 65 增加到 66：

1. 修改 doc_gate，使其从 runner 的 scenes 数组机械读取当前数量。
2. 不再以硬编码 65 作为未来永久门槛。
3. 新增或更新一个唯一的当前测试基线文件，记录自动化场景数和主场景冒烟数。
4. doc_gate 必须验证当前状态文档引用的“当前数量”与 runner 一致。
5. 历史版本记录中的旧数量不得被机械全局替换。
