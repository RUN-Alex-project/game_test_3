6. 负向「UI 绕过 service」改为：生产不提供 `set_relationship_value`；送礼/领奖必须经 GameState 公开方法并带 `operation_id`。

### 6.2 真实变异负向（`work/v143/verify_adventurer_negatives.py`）

先证明变异生效，再走同一正向验证器：

1. 重复冒险者 ID → `ERR_DUP_ADV_ID`
2. 偏好物 ID 不存在 → `ERR_GIFT_PREF_UNKNOWN`
3. 关系阈值乱序 → `ERR_REL_THRESHOLD_ORDER`
4. 委托 ID 重复 → `ERR_DUP_COMM_ID`
5. 委托目标未知物品/怪物/地图 → `ERR_COMM_TARGET_UNKNOWN`
6. 严格 v22 存档缺 expansion_state → `ERR_EXPANSION_MISSING`（仅严格校验；宽松加载 v21 必须仍迁移成功，不走本项）
7. 关系 history 重复 operation_id → `ERR_DUP_HISTORY_OP`
8. 生产存在 `set_relationship_value` → `ERR_DIRECT_REL_SETTER`
9. 加载前弄脏运行时后，v21 迁移仍用合同 seed → 由关系专项正向覆盖，不在本脚本改生产 JSON
10. 同一 reward operation_id 重放 → 由关系专项正向覆盖

本脚本至少覆盖 1–8；9–10 放关系专项。合计仍满足「至少八项真实变异」。
