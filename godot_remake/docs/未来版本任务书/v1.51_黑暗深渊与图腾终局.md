## 1. 版本目标

完成单机长期主线的第一阶段终局：黑暗深渊与图腾试炼。它应把 v1.48–v1.50 的线索、固定 NPC 关系、领地/商会投入和既有最终战整合为可验证的连续流程；不能仅增加一个“终局按钮”或直接把 `game_won` 改为真。

首次目标时长：3–4 小时；完成后解锁有限的周常深渊挑战和终局回顾，不增加无上限奖励源。

本版本不做：赛季、自动战斗、真实多人副本、无限循环深渊层数、重新平衡用户已经签署的覆盖数值。

## 2. 地图与章节状态

### 2.1 新地图

新增 5 张稳定地图：

1. `abyss_gate`
2. `abyss_outer_ring`
3. `abyss_echo_halls`
4. `totem_sanctum`
5. `abyss_heart`

每图必须同步登记到 `maps.json`、世界交互注册表、运行时构建、故事数据和参数化地图测试。出口逐项登记 target、坐标、方向、解锁条件、失败理由和 runtime metadata。

### 2.2 终局状态机

状态严格限定为：

`locked` → `summons` → `abyss_entry` → `echoes` → `totem_trials` → `heart_assault` → `final_battle` → `epilogue_pending` → `completed` → `weekly_abyss`。

1. `summons`：从已完成的篇章/关系/进度收集至少三类真实前置，不要求所有支线满完成。
2. `echoes`：完成 3 个不同“指挥者回响”目标，最多注册 5 个；不采用随机无限刷怪。
3. `totem_trials`：完成三个图腾试炼，分别可引用商会、领地、元素或固定 NPC 系统的真实状态。
4. `heart_assault`：开启深渊之心。
5. `final_battle`：经真实生产战斗完成最终 Boss。
6. `epilogue_pending`：战斗胜利后先结算奖励/关系/报告，再通过真实收束 action 写入完成状态。
7. `completed`：开放回顾和每周深渊委托，但不再重复发放一次性终局奖励。

## 3. 数据、服务与存档

### 3.1 新增数据

1. `data/abyss_finale_story.json`：全部状态、前置、真实 action、奖励、分支和跨日规则。
2. `data/abyss_maps.json`：地图、出口、演员、出现条件。
3. `data/abyss_echoes.json`：3–5 个回响 ID、战斗数据、掉落、一次性/周常规则。
4. `data/totem_trials.json`：三个图腾试炼的真实验证规则和奖励。
5. `data/abyss_rewards.json`：一次性与周常奖励白名单、operation_id 规则。

### 3.2 服务

1. `AbyssFinaleService`：章节状态、前置、图腾试炼、收束。
2. `EchoEncounterService`：回响/最终 Boss 的生成、战斗会话关联、回调验证。
3. `TotemTrialService`：三种试炼的原子验证和结算。
4. `FinaleEpilogueService`：胜利后报告、关系/声望/贡献变化、一次性奖励和完成标记。

所有服务必须接收 session_id、operation_id 或等价不可变标识，拒绝旧回调、重复结算和错地图调用。

### 3.3 v22 字段

`expansion_state.chapters.abyss_finale` 至少包括：

1. `stage`、`echo_completed_ids`、`totem_completed_ids`、`chosen_allies`。
2. `final_battle_status`、`epilogue_status`、`one_time_reward_claimed`。
3. `weekly_abyss`、`last_weekly_claim_day`、`operation_ids`、`ledger`。
4. `chapter_snapshot_version`，用于将来规则升级时做明确兼容，而非读取后静默改写。

## 4. 玩法规则

### 4.1 回响与图腾

1. 回响目标必须在正确 stage/map 出现；每个回响完成一次即可，不可重复刷首次奖励。
2. 图腾试炼不得只检查布尔值。至少分别调用已有系统的真实只读/消耗/关系入口，并把输入快照登记。
3. 失败时所有消耗、关系、声望、资源和阶段必须遵守数据定义的回滚或保留规则；禁止半提交。
4. 回响、图腾和最终战均通过真实交互/战斗路径推进，取消、死亡、切图、session 过期时零推进。

### 4.2 最终战与收束

1. 最终 Boss 只能在 `final_battle` 状态创建，并登记真实 active_monster_id/session_id。
2. 最终战胜利不直接写 `game_won`。先进入 `epilogue_pending`，在真实 epilogue action 后才完成。
3. `game_won` 若作为既有兼容字段，只能由单一生产收束路径写入；测试不得用它伪造成功。
4. 一次性奖励、世界完成、邮件、排行/关系变化必须同一结算事务或有可恢复账本。
5. 周常深渊不能重给一次性奖励；每周快照、敌人和奖励可复现。
