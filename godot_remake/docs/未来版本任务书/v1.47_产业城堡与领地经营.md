## 1. 目标与范围

将已有六处领地挑战扩展为单机长期经营系统：领地带来有上限的日收益、风险事件和治理选择；城堡提供清晰的升级、委任和仓储入口。所有收益由真实日结和已拥有领地决定，绝不能通过重复点击领取。

本版本完成：

1. 六领地的产业规则、风险事件、治理等级和贡献记录。
2. 城堡总览、仓储、委任、升级和领地账本。
3. 固定冒险者委任与关系影响。
4. 领地日结、周结、补偿、事件处理与邮件通知。
5. 与 v1.46 商会、v1.45 排行、既有爵位/军功/领地挑战的联动。

不在范围：新增大地图、无限自动采集、多人公会、真实在线税收、可购买的现实货币资源。

## 2. 数据与状态合同

### 2.1 数据文件

新增：

1. `data/property_rules.json`：城堡等级、升级成本、仓储上限、每日治理次数。
2. `data/territory_economy.json`：六领地 ID、基础产出、资源上限、风险池、解锁要求、贡献规则。
3. `data/territory_events.json`：事件 ID、触发条件、可选处理、消耗、结果、冷却和文本 key。
4. `data/adventurer_assignments.json`：可委任 NPC、岗位、关系阈值、成功率规则、持续日数和不可用原因。

每一个领地必须与现有 `territory` map/challenger 配置双向对应。不存在“只在 JSON 中存在但生产地图没有”的领地，也不存在未登记的生产领地。

### 2.2 服务边界

1. `PropertyService`：城堡升级、仓储、资源上限、委任槽位。
2. `TerritoryEconomyService`：日结产出、资源封顶、风险事件、处理、贡献和账本。
3. `AssignmentService`：固定 NPC 的岗位委任、离任、冷却、收益修正。
4. `TerritoryLedgerService`：每次产出、扣除、补偿和事件结果的 operation_id/幂等记录。

UI、NPC 对话和地图演员只请求服务；不得自行写 `owned_territory`、资源数量或事件完成标记。

### 2.3 v22 字段

使用 `expansion_state.property` 与 `expansion_state.territory_economy`：

1. 城堡等级、仓储内容、升级 operation_id、委任槽位。
2. 每个领地的治理等级、资源库存、最后结算日、事件冷却、处理记录、贡献值。
3. 委任记录：npc_id、岗位、开始日、结束日、快照、状态。
4. 日结/周结 ledger、已处理事件 ID、邮件领取 ID。

字段默认值必须由固定 schema 默认表提供；读档时先 DTO 完整校验再一次性提交。

## 3. 规则

### 3.1 六领地

沿用现有六个领地 ID 和挑战守卫，分别登记唯一产业定位。建议类型为：城镇贸易、雷鸣矿脉、沙漠补给、沼泽药材、冰宫遗物、亚维特航路；实际名称以 v1.42 证据登记和现有 ID 为准。

每个领地必须具有：

1. 基础日产出及资源上限。
2. 治理等级 0–3 的可审计加成。
3. 一个常规风险事件池和至少一个稀有事件。
4. 对应的委任岗位或明确“不支持委任”的数据理由。
5. 贡献值来源与领地贡献榜接口。

### 3.2 日结与事件

1. 只在真实 `advance_day`/既有日结入口发生，按领地 `last_settlement_day` 幂等。
2. 未拥有领地、被锁定领地、资源已满、委任失效时必须输出不同原因。
3. 事件随机性只能来自存档化种子；同日反复加载的事件不变。
4. 处理事件消耗、奖励、关系变化和冷却全部由数据规则驱动。
5. 事件处理成功后重复点击不重复发奖；失败不消耗资源。

### 3.3 城堡与委任

1. 城堡升级前检查金币、魔石、资源、爵位或声望；扣除和升级同一原子事务。
2. 仓储满时不能吞掉产出；可转为邮件或明确保留待领取状态，但规则必须固定且有账本。
3. 同一 NPC 同时只能委任一个岗位；战斗、擂台、邮件任务等不可用状态必须阻止委任且无状态变化。
4. 委任到期、关系下降、解锁状态改变时，按快照/规则结算，不得产生幽灵委任。

## 4. UI 与入口

1. 使用现有领地报名官、城堡/公告入口或明确登记的 NPC 对话 action 打开“领地与城堡”面板。
2. 面板分为：总览、六领地、城堡升级、委任、仓储、事件、账本。
3. 六领地信息必须来自数据列表，不能写六段重复 UI 条件分支。
4. 锁定、未拥有、收益已满、事件冷却、NPC 忙碌、资源不足均显示文本原因。
5. 面板启动隐藏；关闭后不遮挡状态提示；不改变既有 HUD 和原生底栏布局。

## 5. 强制测试

### 5.1 正向

至少新增 `test_property_territory_economy_scene`：

1. 六领地数据与生产 `owned_territory`/挑战配置双向集合一致。
2. 占领后经真实日结获得一次产出，重复日结零增量。
3. 资源上限、仓储满、未拥有、锁定四种状态的结果各不相同。
4. 城堡升级成功/失败的原子状态差和账本。
5. 至少两种固定 NPC 委任成功、冲突阻止、到期清理和关系修正。
6. 常规事件、稀有事件、成功处理、失败处理、重复处理和跨日冷却。
7. 领地贡献进入 v1.45 榜单真实排序。
8. 读档后六领地库存、事件、委任、账本和 operation_id 深比较。
9. 真实 NPC/面板入口和状态提示路径。

### 5.2 真实变异负向

至少 12 项：

1. 生产领地缺数据，或数据领地缺生产入口。
2. 未拥有领地发放产出。
3. 同日重复结算。
4. 超过资源/仓储上限仍增加数量。
5. 重复 event_id 发奖。
6. 已委任 NPC 再委任第二岗位。
7. 忙碌 NPC 被强制委任。
8. 升级 operation_id 重复。
9. 升级只扣资源未升级，或升级未扣资源。
10. 事件种子同日漂移。
11. ledger 与资源变化不一致。
12. 损坏 v22 存档中的负资源、重复委任、非法岗位。

每项均需先证明变异有效，再使用正向同一验证器命中精确 `PROPERTY_`、`TERRITORY_`、`ASSIGNMENT_` 或 `LEDGER_` 错误码。
