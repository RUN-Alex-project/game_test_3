## 1. 版本目标

12 名固定冒险者每日按可复现种子行动，向玩家发邮件，并基于真实账本做直接交易。不做拍卖、排行、PvP、产业、新地图、联网。

## 2. SE 对本任务书的修订（相对初稿）

1. 入口不加卡萨诺地图演员。邮件/交易从现有「冒险者公告板」打开。
2. 服务名锁定：`DayCycleService`、`MailService`、`MarketService`、`ItemProvenanceService`。日结由 `GameState.advance_day` 调用，禁止 UI 直接改账本/mailbox。
3. 日结随机只允许 `world_seed + ended_day + system_id + adventurer_id + event_sequence` 的稳定哈希，禁止 `randi` / `randomize`。
4. 日结给玩家的物品只能走邮件附件；禁止日结直接加玩家金币/魔石/稀有装备。
5. 绑定物仍为 `category == equipment`。无来源或 `source=forged/untradable` 不可交易。
6. 玩法签署不强制重建 exe；未重建不得声称 release gate 通过。
7. 测试基线 69→72，总 RUN 70→73。负向至少 10 项，脚本 `work/v144/verify_day_mail_market_negatives.py`。

## 3. 必须实现

1. 启用 `day_sequence`、`mailbox`、`economy.adventurer_ledgers`、`economy.daily_settlement_log`。
2. 每个 NPC 每个已结束游戏日最多一个动作；同日重放不重复结算。
3. 邮件发送/领取/到期；背包满则领取失败且附件保留。
4. 直接买卖原子变更：玩家背包+货币+NPC 库存+NPC 货币+账本日志；失败全不变。
5. 生产不提供 `transfer_item_to_npc`；UI 只调 GameState 公开方法。

## 4. 日结动作

hunt / gather / train / trade / rest / commission / arena_prep。
采集/猎猎产物进入 NPC 账本。休整可把账本中的玫瑰移入邮件托管。磕台准备只写日志。
结算日 = advance_day 之前的 `current_day`。新档 day=1 不在 `_ready` 结算。
