## 3. 核心规则

### 3.1 收藏册

1. 收藏记录从真实 `pets`/研究所/挑战/掉落状态计算，不能只显示固定完成百分比。
2. 一个宠物实例最多计入规则定义的一个收藏条目；重复实例按数据决定是否计数。
3. 收藏奖励每个 `collection_reward_id` 只可领取一次，背包满时按现有可靠规则处理。
4. 图鉴可显示未获得条目，但不得泄露未登记/未解锁的来源数据。

### 3.2 支援槽

1. 最多一个支援幻兽；必须与两个主动幻兽槽相互独立，且不能与其为同一实例。
2. 支援效果必须为数据表中有限枚举，如探索收益、特定试炼减伤、研究所委托效率；不能直接无限加战斗力。
3. 支援效果只在登记的场景/战斗快照里生效；更换支援后旧 battle session 不得漂移。
4. 失效宠物、未拥有宠物、战斗中换槽、重复回调均不得产生隐形加成。

### 3.3 试炼与研究所委托

1. 三档试炼使用真实地图/挑战/战斗路径，并有固定首通/周常规则。
2. 幻兽王只能在完整前置和正确地图/入口生成，胜利才结算。
3. 研究所委托使用既有研究所真实成本/产量/技术状态；不得绕过库存、魔石、灵魂王或日产量上限。
4. 任何新奖励都必须在数据白名单并写 operation_id/ledger。

## 4. 服务、存档与 UI

### 4.1 服务

1. `PetCollectionService`：图鉴统计、领取、来源审计。
2. `PetSupportService`：支援位、资格、快照注入、撤销。
3. `PetTrialService`：三档试炼/幻兽王生成、结算和周常。
4. `ResearchContractService`：研究所终局委托、成本、结算和幂等。

### 4.2 v22 字段

`expansion_state.pet_endgame`：收藏条目/奖励、支援实例 ID、支援 operation_ids、试炼状态、周常状态、研究所合同、ledger。不得改动已有宠物实例格式，除非先在 schema 注册表中有明确兼容项。

### 4.3 UI

从既有幻兽面板、研究所 NPC 和挑战入口真实进入。新增页签可为：收藏册、支援、试炼、研究委托、周常。所有资料来自服务/数据；新 UI 默认隐藏，不越界，不遮挡状态提示。
