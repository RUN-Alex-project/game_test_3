## 1. 目标

新增冰原远征和元素试炼，给现有单机战斗增加有限、可解释、数据驱动的战术标签。目标不是重写全部战斗，也不是引入难以验证的随机元素伤害。

本版本实现：

1. 5 张冰原/元素地图与一条完整篇章。
2. 火、冰、雷三类可审计元素标签；其余元素保留为后续数据占位，不做空功能。
3. 敌人抗性、场地条件、有限消耗品和一次性解谜门槛。
4. 两个元素 Boss、一个周常试炼、固定 NPC 研究员/向导入口。

不做：大规模职业重构、无限元素叠层、实时联网组队、随机不可复现实验结果。

## 3. 数据合同

新增：

1. `data/element_rules.json`：元素 ID、抗性范围、相克修正、叠层上限、显示文本 key。
2. `data/element_encounters.json`：每个敌人/Boss/场地的元素标签、抗性和阶段规则。
3. `data/ice_element_story.json`：故事节点、调查、解谜、奖励、周常。
4. `data/ice_element_maps.json`：地图、出口、演员、条件。
5. `data/element_consumables.json`：白名单消耗品、使用条件、冷却和效果。

生产中不得将元素倍率散落为未登记常量。战斗服务要提供单一 `ElementResolutionService` 或等价纯规则入口，返回基础值、修正、来源 rule_id、最终值和上限裁切信息。

---

## 4. 战斗与解谜规则

1. 元素修正只发生在登记的战斗事件上；普通物理攻击仍按既有规则，不能意外改变用户既有经验/金币/军功/掉落倍率。
2. 抗性范围固定为数据定义区间；任何结果不得使伤害为负或产生 NaN/Infinity。
3. 场地效果仅在本篇章指定战斗生效，并在 battle snapshot 固化；切图、取消、死亡或旧回调不结算战斗进度。
4. 消耗品只可在数据允许时使用，一场战斗/一天的次数规则必须幂等。
5. 解谜门槛只能由真实物品、故事进度或元素状态满足；失败不消耗关键物品。
6. Boss 仅在对应阶段和地图出现，胜利才推进；可重复周常 Boss 不能重复发放本周奖励。

## 5. 存档与 UI

### 5.1 v22 字段

`expansion_state.chapters.ice_element`：阶段、调查/钥匙集合、元素知识解锁、周常状态、Boss 结果、消耗品冷却、operation_ids、ledger。

对战快照中新增的元素字段必须仅保存在战斗/报告快照，不得污染其他历史战斗或固定 NPC 基础数据。

### 5.2 UI

1. 研究员或向导 NPC 对话提供试炼说明、元素图鉴和真实入口。
2. 战斗报告显示元素 rule_id、基础值、修正和最终值，文案可解释但不能伪造未发生的效果。
3. 任务簿显示故事阶段、门槛、钥匙/调查进度和周常冷却。
4. 任何新增面板都必须通过已有代码型几何/启动隐藏/层级审计。

## 6. 强制测试

### 6.1 正向

新增 `test_ice_element_chapter_scene` 和 `test_element_resolution_scene`，至少覆盖：

1. 五地图、出口、演员和故事注册表双向一致。
2. 三元素规则的边界、相克/抗性、裁切和确定性输出。
3. 真实战斗快照在开始后不受 NPC/日结状态变化影响。
4. 场地效果只影响登记战斗；普通战斗基线不变。
5. 消耗品成功/失败/冷却/重复回调状态差。
6. 故事、解谜、两个 Boss 和周常试炼真实流程。
7. 取消、死亡、切图、旧 session 不能推进或结算。
8. 读档后元素知识、故事、冷却、周常、Boss、账本深比较。
9. 相邻战斗、掉落、经验、固定 NPC、日结、存档、发布门禁回归。

### 6.2 真实变异负向

至少 14 项：未知元素、抗性越界、负伤害、NaN/Infinity、未登记场地影响普通战斗、错误战斗快照、消耗品冷却绕过、关键物品失败仍扣除、未达阶段生成 Boss、取消后结算、周常重复领奖、元素规则与报告不一致、地图合同缺项、损坏存档枚举。

每项必须先证明变异，再经正向同一验证器得到精确 `ELEMENT_`、`ICE_`、`BATTLE_`、`CHAPTER_` 或 `SAVE_` 错误码。
