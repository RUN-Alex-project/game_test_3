## 1. 目标与范围

把现有单机战斗变成有明确目标的后期成长循环：九种固定挑战、有限技能精通、装备词条审计和奖励选择。角色定位保持现有战士，不新增完整法师/异能者职业树。

本版本完成：

1. 九个数据驱动挑战，分布于已完成篇章/既有地图入口。
2. 三至四个战士技能精通节点，建立在已有技能/战斗反馈系统上。
3. 有限装备成长槽和挑战勋章，不引入无限随机词条。
4. 挑战记录、回放报告、周常轮换、排行/冒险者协同。

不做：付费概率、无限重铸、实时 PVP、破坏既有装备/幻兽/经验机制的大规模重写。

## 3. 技能与装备规则

### 3.1 技能精通

仅针对已有可用战士技能，建议涉及飞天连斩、星魔剑及两个现有战斗动作对应的精通节点。每个精通节点必须：

1. 有固定解锁条件、消耗和唯一 `mastery_id`。
2. 通过 `SkillService`/战斗真实路径生效，不在 UI 文本里伪加数值。
3. 有明确上限；重复解锁不得再次扣费或加成。
4. 在 battle snapshot 中固化，战斗中不因读档/日结漂移。
5. 不修改用户已确认的技能书掉率翻倍规则，仅可使用其已获得书/材料作为条件。

### 3.2 装备成长

1. 每件装备至多拥有数据规则定义的有限挑战槽；不得随机无限刷词条。
2. 词条只能来自挑战奖励白名单；绑定装备 instance_id、来源 challenge_id 和 operation_id。
3. 品质/魔魂“必成”等既有用户覆盖规则不得被重置、削弱或重复放大。
4. 更换、拆除、失败和背包满必须遵循原子规则与明确补偿。

### 3.3 奖励与轮换

1. 首次奖励每挑战一次；周常奖励按挑战轮换和周种子一次。
2. 训练/回忆模式可重玩，但不得影响首次/周常奖励、排名和用户数值。
3. 排行/擂台仅使用挑战完成记录和快照，不能由 UI 填写分数。

## 4. 服务、存档与 UI

### 4.1 服务

1. `ChallengeService`：挑战创建、前置、快照、结算和幂等。
2. `WarriorMasteryService`：解锁、查询、上限和 battle snapshot 注入。
3. `EquipmentMasteryService`：槽位、绑定、拆除、审计账本。
4. `ChallengeRotationService`：周轮换和奖励快照。

### 4.2 v22 字段

`expansion_state.challenges`、`expansion_state.warrior_mastery`、`expansion_state.equipment_mastery`，包含所有完成记录、奖励领取、周种子、operation_id、装备绑定和 ledger。读取必须 DTO-first 深验证。

### 4.3 UI

1. 通过现有挑战官/PK 官/任务簿等真实入口打开挑战簿。
2. 面板至少有：九挑战列表、当前规则、奖励、历史报告、技能精通、装备挑战槽、周轮换。
3. 被锁定、次数耗尽、条件不足、背包满、装备不合法、训练模式均有明确文本。
4. 新面板遵守既有启动隐藏、关闭、状态提示、边界和层级审计。
