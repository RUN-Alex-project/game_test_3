## 1. 目标

新增第一条可重复游玩的单机扩展主线：树心异常与海港走私。该篇章应提供探索、调查、分支选择、固定 NPC 合作、Boss、奖励和收束，不把内容做成一次对话后直接给终态。

建议游玩时长：首次 2–3 小时；解锁后每周可进行有限重玩的委托与精英挑战。数值以现有 v1.41 及已签署覆盖值为基础，不重置用户已有进度。

---

## 2. 地图、任务与故事范围

### 2.1 新地图合同

新增 6 个 map_id，名称可本地化，但 ID 必须稳定：

1. `treeheart_outskirts`
2. `treeheart_core`
3. `harbor_quay`
4. `harbor_market`
5. `sea_cave`
6. `tide_shrine`

每张地图在 `maps.json`、世界交互注册表、运行时构建和参数化测试中双向存在。每个出口必须具备 target、方向、位置、尺寸、解锁规则和失败文本。不得用地图选择按钮替代边缘出口或 NPC 传送的既有交互规范。

### 2.2 主线阶段

1. `treeheart_rumor`：树心城线索与冒险者会面。
2. `root_sickness`：采集/调查三个证据点。
3. `harbor_lead`：在港口发现走私账本。
4. `smuggler_choice`：选择公开举报或秘密追踪；两者均可继续主线，但关系和商会收益不同。
5. `sea_cave_assault`：进入海洞，完成阶段 Boss。
6. `tide_shrine_finale`：潮汐祭坛首领和篇章收束。
7. `treeheart_weekly_contract`：解锁后每周委托，受日结和周结幂等约束。

### 2.3 固定 NPC 使用

至少使用 v1.43 的 4 名既有固定冒险者，并定义不同角色：调查、护卫、交易辨识、线索协调。不得新增“随机在线玩家”或网络依赖。

## 3. 数据与服务

### 3.1 数据文件

新增：

1. `data/story_treeheart_harbor.json`：状态节点、前置、真实 action、奖励、分支、跨日规则。
2. `data/treeheart_harbor_maps.json`：仅扩展地图数据/引用，不复制大段代码。
3. `data/treeheart_harbor_encounters.json`：怪物、Boss、掉落、精英/周常规则。
4. `data/treeheart_harbor_npcs.json`：本篇 NPC action、对话 key、出现条件。
5. `data/treeheart_harbor_rewards.json`：奖励白名单、一次性与周常次数规则。

资源引用必须来自 v1.42 的内容证据/资源登记，或由 PM/SE 事先批准的本地资源清单。禁止整包导入 2.x 文件，禁止把未登记资源当作“已确认原版资源”。

### 3.2 服务

1. `StoryChapterService`：阶段推进、分支、前置验证、重复/跨日规则、篇章收束。
2. `ChapterEncounterService`：按故事阶段生成/移除演员，创建真实战斗 session。
3. `EvidenceCollectionService`：调查点/账本/线索收集的 operation_id 和去重。
4. `WeeklyContractService`：每周委托生成、开始、结算和周重置。

服务返回结构化错误码；地图和 UI 不直接写主线终态或掉落。

### 3.3 v22 字段

`expansion_state.chapters.treeheart_harbor` 至少包含：

1. `stage`、`branch`、`collected_evidence_ids`、`completed_operation_ids`。
2. `boss_status`、`weekly_contract`、`last_weekly_claim_day`。
3. `npc_snapshot_ids`、`reward_claims`、`chapter_ledger`。

所有一次性奖励、周常奖励、收集物和 Boss 结算必须可读档深比较。

## 4. 规则与真实流程

1. 每个主线阶段由数据定义实际前置；不能通过设置 `stage=finale_complete` 来跳过调查、分支或战斗。
2. 调查点只能在正确 map/stage 下操作一次；失败、无权限、离开地图、旧回调均不增加证据。
3. 分支锁定后不可反复切换；分支结果影响固定 NPC 关系/商会奖励，但不得让主线永久不可完成。
4. Boss 出现/消失必须由真实 stage 触发；战斗胜利才可推进，取消/死亡/切图不得推进。
5. 周常每周最多结算一次；当前周的种子和奖励快照稳定，跨周真实日结后才刷新。
6. 掉落必须使用既有掉落/背包原子路径；背包满时遵循现有明确规则，不吞物品。

## 5. UI、文本与资源

1. 使用真实 NPC 对话、地图演员、边缘出口、任务簿和既有战斗流程；不新增简陋的“地图列表替代品”。
2. 任务簿显示当前阶段、调查进度、分支锁定状态、下一步提示、周常委托冷却。
3. 港口账本、调查点和 Boss 交互对象必须有可解释文本，未解锁时不可静默。
4. 不修改顶部 HUD 的已签署几何规则；新面板默认隐藏，关闭路径和状态提示必须可验证。
5. 本版本新增的文本均以本地化 key 或集中数据存储；不要在测试中靠中文全文硬编码驱动流程。

7. 任务簿、NPC 对话、地图出口、状态提示和面板层级真实路径。
