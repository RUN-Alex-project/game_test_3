## 第三轮报告被证伪表述的更正

- **"版本横幅 = 主场景启动标记" 撤销**：第三轮冒烟以 Godot 版本横幅作为主场景启动证据——不成立。本轮在生产主场景 `main_original.gd` 的 `_ready` 末尾输出稳定标记 `APP_READY:main_original`，冒烟日志必须命中该标记；单独版本横幅不再作为启动证据。
- **"wrong_hash 与正向同路径" 更正**：第三轮 smoke 的 wrong_hash 走"注入已知错误值即 exit 1"专用分支——不成立。本轮重写为：复制发布目录到临时目录，真实篡改 manifest / SHA256SUMS，调用**与正向完全相同的 hash validator**（`Test-HashThreeWay`），负向通过"篡改被同一 validator 拒绝"成立。
- **"rc_tmp 每次删除均检查返回值" 仅在代码真正实现后声明**：本轮 `_remove_dir_recursive` 每个 remove 均断言 `== OK`，并由调用方断言 rc_tmp 目录不存在。
- **正向能运行 ≠ 门禁不可逃逸**：本轮所有结论以"负向被同一验证器拒绝"为门禁证据，不再以正向可运行反推不可逃逸。

## 第四轮拒签清单 → 本轮修复对照

### 〇、补充整改（本轮一次性修复）：policy 强制 / 共用验证器 / Remove-Dir / 报告口径

**1. precondition_policy 强制**：`_run_precondition` 要求 precondition_policy 字段必须存在且精确为 `required`/`not_applicable`——缺失 → `STORY_PRECONDITION_POLICY_MISSING`，未知值（空串/typo/大小写错误）→ `STORY_PRECONDITION_POLICY_INVALID`。新增 N27-N30 负向（删除 policy/空串/`requried` typo/`REQUIRED` 大小写），每项先证明变异生效再精确命中。恢复后审计精确统计 **26 required + 1 not_applicable**（无缺失/未知）。

**2. 共用进程结果验证器**：smoke 抽出 `Invoke-ProcessCheck`（检查 timeout / 自然退出 / ExitCode / 日志路径），**正向、early_exit、timeout 负向全部调用同一函数**。

**3. 日志负向前置证明**：log_script_error / log_error / ready_missing 负向先证明**同一次 EXE 运行**自然退出 + ExitCode=0 + **原日志通过 Test-Log**，再注入/删除目标内容并证明变异生效，最后同一 `Test-Log` 拒绝。

**4. Remove-Dir 修复**：删除靠 `-ErrorAction Stop` 捕获失败（不再把 Remove-Item 无返回值当布尔），删除后 `Test-Path` 验证目录不存在。新增 `cleanup_nested` **清理专项场景**：建含嵌套子目录的临时目录 → Remove-Dir → 验证不存在（清理能力验证，非故障注入）。

**5. 报告口径**：不再笼统声称"9 个负向全部走同一验证器"，改为真实结构——**每类正负向共用相同验证器**：哈希类共用 `Test-HashThreeWay`（正向 4 负向）、日志类共用 `Test-Log`（正向 3 负向）、进程类共用 `Invoke-ProcessCheck`（正向 + early_exit + timeout）、清理类共用 `Remove-Dir`+`Test-Path`（cleanup_nested 清理专项场景）。

### 一、封闭 not_applicable 旁路

**拒签指摘**：`_run_precondition` 只查 not_applicable 理由非空，不校验该节点是否允许；只依赖 `_ready` 外层审计；三集合覆盖在调用前登记。

**修复**（tests/test_story_dialogue_state_machine_scene.gd + story_dialogue_registry.json）：
- 注册表每节点顶层加 `precondition_policy = "required" | "not_applicable"`（仅 prime_minister_king_news 为 not_applicable，其余 26 为 required）。
- **`_run_precondition` 执行器自身校验**（不依赖外层审计）：
  - `policy == "not_applicable"`：先经 `_is_not_applicable_allowed(node_id)`（独立允许集合 {prime_minister_king_news}）校验；未标 not_applicable → `STORY_PRECONDITION_NOT_APPLICABLE_INVALID`；理由空 → `STORY_PRECONDITION_REASON_MISSING`。
  - `policy == "required"`：若标 not_applicable（**即使带非空假理由**）→ `STORY_PRECONDITION_NOT_APPLICABLE_INVALID`；缺 precondition_setup/action → `STORY_PRECONDITION_CONFIG_MISSING`。
- **三集合覆盖只在 `_run_precondition` 真正完成校验后登记**：新增 `_precondition_verified`，`run_registry_case` 中 `pre_code == ""` 后才登记；_ready 三集合断言用该集合（注册表 == 执行 == 前置校验完成 = 27）。
- **4 个同执行器负向**：N14 rescue_king 标 not_applicable + 非空假理由 → INVALID；N23 king_dialogue 标 not_applicable + 非空理由 → INVALID；N24 prime_minister 改 required 缺配置 → CONFIG_MISSING；N26 rescue_king 改 policy=not_applicable（不在允许集）→ INVALID；N25 合法 prime_minister not_applicable 正向保真通过。

### 二、重构 exe 冒烟为真实可复用验证器

**拒签指摘**：SHA 验证用 `$shaHash != ""` 跳过比较；wrong_hash 走专用"已知错误值 exit 1"分支；日志只匹配少数模式。

**修复**（work/smoke_release_exe.ps1 重写）：
- **可复用 `Test-HashThreeWay`**：exe 实际存在、manifest 恰好一条 exe（executable + executable_hash_sha256 且 64 hex）、SHA256SUMS 恰好一条 exe 行、三者哈希**精确相等**。条目缺失 / 重复 / 格式错误全部失败（无 `!= ""` 跳过）。
- **wrong_hash 负向**：复制发布目录到临时目录 → 真实篡改 manifest 的 executable_hash_sha256 → 调用同一 `Test-HashThreeWay` → 必须拒绝（无专用分支）。
- **可复用 `Test-Log`** 多行匹配（`(?m)`）：`SCRIPT ERROR:` / `^ERROR:` / `FAILED` / `Assertion failed` / `ObjectDB instances leaked`，且必须命中 `APP_READY:main_original`。
- **负向（同一验证器）**：sha_missing（删 exe 行）、sha_dup（重复 exe 行）、sha_bad_format（格式错误行）、wrong_hash（篡改 manifest）、log_script_error（注入 SCRIPT ERROR）、log_error（横幅后注入普通 `ERROR: injected`）、ready_missing（删 ready 标记）、early_exit、timeout。
- 失败日志保留、正向成功日志删除、临时目录递归删除检查返回值。

### 四、统一 release gate（work/run_release_gate.ps1）

顺序执行（每步校验预期退出码，任一不符 → gate Exit 1）：
1. `python docs/doc_gate.py`（Exit 0）
2. 正向 exe 自然退出冒烟（Exit 0，命中 APP_READY）
3. SHA 缺失/错误/重复/格式负向（各 Exit 1）
4. early non-zero exit 负向（Exit 1）
5. SCRIPT ERROR 与普通 ERROR 日志负向（各 Exit 1）
6. timeout 负向（Exit 1）
7. ready 标记缺失负向（Exit 1）
8. 全部通过输出唯一 `RELEASE_GATE PASS`。

gate 逐步日志（含失败日志路径）写入 `C:\Users\Public\release_gate.log` 供交付报告引用。
