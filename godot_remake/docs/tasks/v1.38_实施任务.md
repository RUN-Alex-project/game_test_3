# v1.38 实施任务书

版本主题：剧情与对话分支完整性  
执行角色：资深 Godot 开发工程师  
评审角色：项目经理 / 系统工程师  
发布时间：由用户正式交付本任务书时填写  
前置门禁：v1.37 已由 PM/SE 正式验收  
版本限制：只实施 v1.38，不开始 v1.39

## 1. 版本目标

把当前“主线能够通关”提升为“关键 NPC 的前置、首次触发、重复交互、跨日和读档分支都有证据、有状态机、有精确反馈”。

本版本只修剧情路由、文本和幂等性，不调整奖励数值，不重做对话 UI，不新增地图或新剧情。

## 2. 必须覆盖的剧情域

1. 地下城三层救王：未救、首次击败、奖励、回宫、重复击败。
2. 国王/首相/元帅：救王前后消息、六类魔军情报、军情/军衔说明缺口。
3. 公主与侍女：聊天、99/999玫瑰、知己礼物、周日礼物、年猪、高级战斗力石。
4. 后花园与抽奖：门槛、传送、首次/重复交互、资源不足。
5. 日常官：星期一至星期日选项、交付、训练幻兽、任务入口。
6. PK：星期六、三级分组、报名、失败/退出、击败后、当天重复。
7. 五福娃：使者出现、草原战斗、五次领取、最终交付、已完成重复交互。
8. 战魂秘密：全身极品前置、任务开放、探险家、付费进入、箱子、守卫、完成后。
9. 最终战：国王情报、六类敌人 alive/dead、跨日复活、主帅门禁、魔的能量、结局后。
10. 研究所与 v1.34 NPC progression 路由作为相邻回归，不能重新导回聚合窗。

## 3. 证据与剧情注册表

新增：

- `docs/evidence/story_dialogues_v103_v9.txt`

按 NPC /剧情域登记：

- `node_id`、`npc_id`、`map_id`

文本使用 SWF 原字符串或有证据的等价表述。无法确认的文本标 `evidence_gap`，不得写成 `native_confirmed`。

## 4. 状态机规则

1. 一次性对白、一次性奖励和可重复信息页必须分开，不得通过“背包中是否还有某物品”推断是否领取。
2. 优先使用现有 `story_flags`、`fuwa_event`、`demon_campaign`、任务状态和 last-day 字段。
3. 如需新增一次性标记，优先增加 `story_flags` 内部 key；必须提供默认值、存档写入、v21 旧档缺省和读档测试，不新增顶层持久字段。
4. 奖励仍调用现有 GameState 原子方法；不得在对话脚本复制扣除/发奖公式。
5. 失败路径必须资源不变、flag 不变、领取日不变。
6. 每次对话生成的 options 必须与当前状态一致；隐藏不可用选项和灰显策略按 SWF 证据决定，不能混用。
7. 结局完成后，旧战役 NPC/敌人不得被对话重新激活。
8. NPC 原生流程不得打开 `progression_panel`，VIP 聚合窗仍作为便捷入口独立保留。

## 5. 自动化测试

新增：

- `tests/test_story_dialogue_state_machine_scene.gd`
- `tests/test_story_dialogue_state_machine_scene.tscn`

采用数据驱动场景矩阵。每个节点至少验证：

- 前置未满足：选项/文本及零状态差。
- 首次成功：真实按钮/dispatcher、精确资源和 flag 状态差。
- 重复交互：奖励不重复、信息页仍可读或按证据关闭。
- 跨日：日常/每周状态按规则重置，一次性剧情不重置。
- 保存并加载 v21：状态与可用选项一致。

必须覆盖第2节十个剧情域，不得只用少量代表场景宣称全部完成。

负向至少包含：

- 删除前置条件 → `STORY_PRECONDITION_UNCOVERED`。
- 首次与重复共用奖励 action → `STORY_REWARD_NOT_IDEMPOTENT`。
- 篡改 option/action 映射 → `STORY_ACTION_ROUTE_MISMATCH`。
- 缺失读档默认 flag → `STORY_SAVE_DEFAULT_MISSING`。
- 原生 NPC 打开 progression panel → `STORY_NATIVE_ROUTE_LEAKED_TO_AGGREGATOR`。
- 篡改 evidence token → `EVIDENCE_TOKEN_MISS`。

所有负向必须调用与正向状态机相同的验证器。
