# v1.34 实施任务书

版本主题：剩余系统入口的原版流程校正  
执行角色：资深开发工程师  
评审角色：项目经理 / 系统工程师  
发布日期：2026-07-29  
前置基线：v1.33已正式验收通过，48个自动化场景加主场景冒烟全部通过

## 1. 版本目标

区分“原版NPC对话入口”和“便捷聚合窗口”。

军衔/军饷、爵位捐献、玫瑰赠礼、日常功勋、公主礼物和幻兽研究所必须能从各自原版NPC的对话与专属窗口完成。底栏VIP打开的成长聚合窗可以保留为便捷入口，但不得继续充当这些NPC的唯一交易入口，也不得被文档或测试称为原版NPC流程。

本版本只校正入口、对话路由、原子结算反馈及相应测试。不得借机调整已确认的数值、奖励、日期机制、存档或大范围UI。

## 2. 当前基线与已确认缺口

### 2.1 当前已有的正确入口

- 元帅已有独立 `military_salary`，可直接领取军饷。
- 首相已有 `prime_merit`、`prime_king`、`prime_nobility` 查询对话。
- 公主已有 `princess_chat`、`princess_friend_gift`、`princess_sunday_gift`。
- 研究所NPC使用 `research` 打开专属 `ResearchPanel`；资助、产量任务和购买均已存在于专属窗口。
- 周三/周四日常官可打开幻兽窗口，幻兽详情已有“上交日常”。
- 周五、周六、周日任务入口已经分别路由到雪域任务、PK赛和地下城。

这些正确入口应保留，除非ActionScript文本证据明确要求校正标签或前置条件。

### 2.2 当前必须修正的聚合窗替代入口

`scripts/main_original.gd` 当前仍存在以下错误路由：

| NPC | 当前选项 | 当前action | 问题 |
|---|---|---|---|
| 元帅 | 战功查询 | `progression` | 打开成长聚合窗，不是元帅专属查询流程 |
| 元帅消息页 | 战功查询 | `progression` | 同上 |
| 首相 | 捐献金币 | `progression` | 打开聚合窗，未由首相对话完成捐献 |
| 首相爵位说明页 | 捐献金币 | `progression` | 同上 |
| 公主 | 送礼 | `progression` | 打开聚合窗，未由公主对话完成玫瑰赠礼 |
| 日常任务官周一/周二 | 交付宝石 | `progression` | 打开聚合窗，未由任务官对话完成材料交付 |

这是v1.34的核心缺口。修复后，上述NPC路径在 `progression_panel` 始终隐藏、甚至未调用 `_toggle_progression()` 的情况下仍必须完整可用。

## 4. 实施要求

### 4.1 元帅：军衔、军功、军饷

1. 保留 `military_salary` 直接领取路径。
2. 将两处 `progression` 的“战功查询”改为元帅专属action，例如 `military_status`；最终命名可调整，但必须语义稳定、唯一并登记。
3. 专属查询对话至少显示：
   - 当前军功。
   - 当前军衔。
   - 下一军衔及还差多少军功；满级时明确说明已达最高军衔。
   - 当前军衔带来的战斗力。
4. 查询页提供返回元帅主页和离开，不打开成长聚合窗。
5. 军饷继续沿用现有 `GameState.claim_military_salary()`：
   - 非周日不发放。
   - 无军衔不发放。
   - 当周已领取不重复发放。
   - 成功仍按已确认用户覆盖值结算。

### 4.2 首相：爵位、功勋与金币捐献

1. 保留功勋查询、国王消息、爵位说明。
2. 将两处“捐献金币”从 `progression` 改为首相专属捐献对话。
3. 捐献档位必须先依据ActionScript证据确认。现有 `750,000` 与 `75,000,000` 可作为待核对候选，不得仅因聚合窗存在就宣称两档均为原版。
4. 每个确认的捐献档位使用可测试的独立action；结算统一调用 `GameState.donate_gold_for_nobility(amount)`，不得复制功勋公式。
5. 成功后显示实际扣除金币和增加功勋；失败时金币、功勋均保持不变。
6. 捐献完成后仍留在首相对话链，提供继续捐献、返回和离开。

### 4.3 公主：玫瑰、亲密度与礼物

1. 将“送礼”从 `progression` 改为公主专属赠礼对话。
2. 99朵、999朵档位及标签必须以ActionScript证据确认；结算统一调用 `GameState.give_roses(count)`。
3. 成功反馈显示实际玫瑰消耗、亲密度增加和当前关系称号；必须保留用户覆盖的玫瑰好感度加成，不得重算或改写倍率。
4. 玫瑰不足时不扣物品、不加亲密度。
5. 保留聊天、知己礼物和周日礼物的现有独立路径；不得把它们重新并入成长聚合窗。
6. 周日礼物失败时保持现有原子性：背包满、非周日、关系不足或已领取均不得错误写入领取日。

### 4.4 日常任务官：全周入口

1. 周一/周二将“交付宝石”改为任务官专属交付对话。
2. 交付魔魂晶石和灵魂王分别使用独立action并调用 `GameState.complete_daily_task()`，不得复制奖励公式。
3. 成功显示消耗材料及实际功勋；材料不足或当天已完成时不得扣除任何资源。
4. 周三/周四继续从任务官进入幻兽选择/详情流程，并能通过现有“上交日常”完成任务；测试必须从NPC入口开始，不能直接调用 `GameState.submit_pet_for_daily_task()` 代替入口验收。
5. 周五、周六、周日保留现有任务/地图入口，并纳入统一路由测试，防止本次match修改造成回归。
6. 本版本不擅自新增星期限制到 `GameState` 结算函数，也不修改日常奖励数值；如ActionScript证据与当前前置条件冲突，先在交付报告列为待PM决策，不扩大实现范围。

### 4.5 幻兽研究所

1. 反查研究所NPC的原始选项和专属窗口动作，确认“进入研究所”、资助、产量任务、购买的对应关系。
2. 若现有 `ResearchPanel` 路由与证据一致，只补注册表和入口测试，不为了制造改动而重写。
3. 必须从地图中的 `research` NPC对话触发专属窗口，再测试：
   - 资助技术。
   - 完成产量任务。
   - 购买库存幻兽。
4. 保持已确认机制：
   - 技术等级上限300。
   - 产量任务每次日产量+2。
   - 日产量上限6。
   - 现有成本、库存、品质和售价公式不变。
5. 材料不足、魔石不足、无库存、幻兽仓满和达到上限时不得错误扣资源。

### 4.6 成长聚合窗的定位

1. `ProgressionPanel`可以继续由底栏VIP作为便捷入口。
2. 不要求删除聚合窗，也不要求改其布局。
3. NPC action不得再用 `progression` 代替元帅、首相、公主或日常官的原生流程。
4. 更新代码注释和文档，将其明确称为“便捷聚合窗”，不得称为“原版NPC窗口”。

## 5. 自动化测试

新增一个正式测试场景：

- `tests/test_native_npc_progression_routes_scene.gd`
- `tests/test_native_npc_progression_routes_scene.tscn`

并加入 `run_tests.ps1`，正式场景数由48变为49。

### 5.1 必测断言

测试必须实例化 `scenes/main.tscn`，从NPC入口和对话action开始，不得只测服务层。

1. 元帅：
   - 打开NPC对话后存在专属军功查询action。
   - 查询显示当前/下一军衔，不打开 `progression_panel`。
   - 周日军饷成功一次，第二次失败且不重复加魔石。
2. 首相：
   - 从NPC对话进入捐献档位。
   - 成功档正确扣金币和加功勋。
   - 金币不足时两个字段均不变。
   - 全程不打开 `progression_panel`。
3. 公主：
   - 从“送礼”进入玫瑰选项。
   - 99朵或经证据确认的档位成功结算。
   - 玫瑰不足失败且状态不变。
   - 公主周日礼物仍可从公主对话领取。
4. 日常任务官：
   - 周一/周二分别完成一种材料交付。
   - 重复交付和材料不足均不扣资源。
   - 周三/周四能由NPC入口到达可执行幻兽上交的界面。
   - 周五任务接取、周六PK入口、周日地下城入口仍可达。
5. 研究所：
   - 从地图NPC对话打开专属 `ResearchPanel`。
   - 至少各覆盖一次资助、产量任务和购买的成功状态差。
   - 至少覆盖材料不足或无库存的一条失败状态差。
6. 聚合窗隔离：
   - 以上所有NPC流程开始前显式隐藏 `progression_panel`。
   - 每一步断言其未被意外打开。
   - NPC action清单中不再把 `progression` 用作上述四类流程。
7. 注册表：
   - JSON结构完整。
   - 每个登记action在 `main_original.gd` 或对应专属panel中存在。
   - 每个 `evidence_source + evidence_tokens` 可验证。
