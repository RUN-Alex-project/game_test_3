# v1.35 实施任务书

版本主题：全地图演员与交互覆盖审计  
执行角色：资深开发工程师  
评审角色：项目经理 / 系统工程师  
发布日期：2026-07-29  
前置基线：v1.34正式验收通过，49个自动化场景加主场景冒烟全部通过

## 1. 版本目标

对当前28张地图进行结构化、可机检的演员与交互覆盖审计。

本版本不是“凭感觉往地图里多放NPC”，而是建立以下闭环：

1. SWF文本证据。
2. 结构化世界交互注册表。
3. Godot活动运行时实体。
4. 参数化自动化测试。

最终必须能回答每张地图：

- 使用哪张背景。
- 有哪些出口，通向哪里，受什么条件限制。
- 有哪些NPC、怪物、交互物和纯装饰。
- 每个实体的坐标、尺寸、资源、action ID及出现条件。
- 动态剧情前后哪些实体出现或消失。
- 每个交互是否有可达处理路径。

## 4. 世界交互注册表

新增：

`docs/world_interaction_registry.json`

### 4.1 顶层结构

至少包含：

- `registry_version`
- `baseline_version`
- `canvas`
- `maps`
- `dynamic_scenarios`
- `evidence_gaps`
- `intentional_divergences`

`maps`必须恰好28项，ID与 `data/maps.json`一一对应。

### 4.2 每张地图

每张地图至少登记：

- `map_id`
- `name`
- `background`
- `swf_scope`
- `exits`
- `entities`

### 4.3 出口

每个出口至少登记：

- `direction`
- `target_map_id`
- `position`
- `size`
- `availability`
- `required_level`
- `action_route`
- `evidence_source`
- `evidence_tokens`
- `implementation_source`

NPC传送、剧情单向传送和普通场景边缘出口必须明确分类，不能全部伪装成地图边缘按钮。

### 4.4 实体

每个实体至少登记：

- `entity_id`
- `kind`
  - `npc`
  - `monster`
  - `interactive_prop`
  - `decoration`
- `display_name`
- `asset`
- `position`
- `size`
- `action_id`
- `action_route`
- `appearance_condition`
- `evidence_source`
- `evidence_tokens`
- `implementation_source`
- `classification`
  - `native_confirmed`
  - `intentional_divergence`
  - `evidence_gap`

规则：

- 同一地图所有 `entity_id`唯一。
- 同一状态下所有非空 `action_id`唯一。
- 同种怪物多实例必须有唯一后缀，例如 `@1/@2`。
- 纯装饰不得伪造交互action。
- 动态实体不得登记为永久常驻。

## 5. 运行时可审计标识

当前 `interactive_actors`可识别交互演员，但纯装饰缺少稳定ID。

允许在不改变视觉和交互行为的前提下：

- 为 `_add_actor()`创建的节点增加metadata：
  - `world_entity_id`
  - `world_entity_kind`
- 为 `_add_decoration()`增加稳定 `entity_id`参数或metadata。
- 为 `NativeExitButton`增加可读的审计metadata。

不得仅依赖场景树子节点顺序识别实体。

不得为了审计重写整个演员系统或把所有硬编码一次性迁入JSON。

## 6. 28图审计与修正

### 6.1 背景与地图ID

逐图检查：

- 背景资源存在。
- `maps.json`与活动运行时背景一致。
- 注册表背景一致。
- 所有出口目标地图存在。
- 没有孤立的错误map ID。

### 6.2 出口

逐图检查：

- 方向唯一。
- 位置和尺寸与SWF证据一致。
- 目标正确。
- 门槛正确。
- 未使用方向隐藏。
- NPC入口、剧情入口和场景边缘入口职责不混淆。
- `war_soul_seal_maze`等特殊地图没有被错误要求必须有普通边缘出口。

如发现SWF与 `maps.json`冲突：

- 先记录证据。
- 只修有明确证据的字段。
- 不凭对称性猜出口。

### 6.3 NPC与交互物

逐图检查：

- 原版NPC是否存在。
- 图片、坐标、尺寸和名称是否正确。
- action ID是否有handler。
- 点击后是否进入专属NPC流程。
- 商店、仓库、研究所、皇宫、领地、抽奖、矿点、战魂箱等入口是否可达。

### 6.4 怪物

逐图检查：

- `maps.json.encounters`与实际世界实例一致。
- 多实例action唯一。
- action可规范化为有效monster ID。
- 地图Boss、蜘蛛、蜘蛛王后、地下城Boss、PK Boss和最终战敌军条件正确。
- 不在本版本修改等级、掉落、军功或战斗数值。

### 6.5 装饰

逐图检查：

- 装饰资源存在。
- 坐标与尺寸有证据。
- 不遮挡或吞掉交互演员的鼠标事件。
- 五福娃、花坛、封印箱周边等剧情装饰随状态正确出现。

## 8. 自动化测试

新增：

- `tests/test_world_interaction_registry_scene.gd`
- `tests/test_world_interaction_registry_scene.tscn`

加入 `run_tests.ps1`，正式自动化场景由49变为50。

### 8.1 注册表结构测试

断言：

- 28张地图且无重复ID。
- 与 `data/maps.json`集合完全相同。
- 每个背景、资源和implementation路径存在。
- evidence token可命中。
- 所有出口目标存在。
- 同图entity/action唯一。
- classification合法。
- 未确认内容进入 `evidence_gaps`，不伪装为confirmed。

### 8.2 运行时参数化测试

对28张地图逐一：

1. 设置明确GameState夹具。
2. 调用活动主场景 `_apply_current_map()`。
3. 比较：
   - 背景。
   - 边缘出口集合。
   - 实体集合。
   - asset。
   - position。
   - size。
   - action ID。
4. 断言实体边界位于700×512地图可玩区域内。
5. 断言纹理和action节点不吞掉不属于自己的交互。

对于顶部HUD或底栏覆盖区域，按SWF原始坐标判断，不得为了通过测试擅自移动演员。

### 8.3 动态矩阵测试

使用第7节场景矩阵逐项实例化或重建地图，断言实体精确集合。

测试结束必须恢复或隔离GameState夹具，不能让一个状态污染下一个状态。

### 8.4 action可达性

至少按action类型各执行一条真实路径：

- 普通NPC对话。
- 商店/仓库。
- 研究所。
- 普通怪物和Boss。
- 领地报名官。
- 矿点。
- 抽奖箱。
- 战魂箱/守卫。
- 地图边缘出口。
- NPC传送。

其他同类action可以用参数化handler存在性验证，不要求在一个测试内把所有怪物打死。

## 9. 允许修正

只有在注册表与SWF文本证据确认后，允许修改：

- `scripts/main_original.gd`中的演员、装饰、出口实例化。
- `data/maps.json`中的背景、出口、encounters清单。
- 与审计metadata直接相关的小型脚本。
- 相关测试和文档。

如果发现需要修改以下内容，停止该项并提交PM决策：

- 战斗数值。
- 掉落。
- 任务奖励。
- 存档字段。
- 大范围场景架构。
- 新地图或新剧情。

## 10. 不得修改

- 不调整用户覆盖数值。
- 不改经验、军功、功勋、玫瑰、研究所、装备或幻兽公式。
- 不重写SceneBattleController。
- 不重新接入legacy地图/战斗面板。
- 不删除legacy脚本。
- 不凭截图或对称性猜坐标。
- 不把动态演员改为永久常驻。
- 不开始v1.36动画时间轴工作。
- 存档版本保持v21。
