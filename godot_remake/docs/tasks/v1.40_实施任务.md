# v1.40 实施任务书

版本主题：存档架构与边界场景加固（条件性 v22）  
执行角色：资深 Godot 开发工程师  
评审角色：项目经理 / 系统工程师  
发布时间：由用户正式交付本任务书时填写  
前置门禁：v1.39 已由 PM/SE 正式验收  
版本限制：只实施 v1.40，不开始 v1.41

## 1. 版本目标

把当前 `GameState.save_game/load_game` 的直接读写拆为可验证的 DTO、规范化和事务式提交过程，保证旧档迁移、边界状态、损坏文件和写入中断不会污染有效内存状态或破坏上一份可用存档。

版本号是否从 v21 升到 v22 必须由 schema 审计结果决定。**不得为了匹配任务标题而无意义升版。**

## 2. Schema 决策门禁

开发开始后先提交一页 `schema_decision`：

- v1.36～v1.39 是否新增顶层持久字段。
- `story_flags` 内新增 key 是否可由 v21 默认规范化兼容。
- DTO/原子写入是否改变磁盘格式。
- 是否确实需要 v22。

只有新增了旧 v21 无法无损表达的持久信息，或磁盘结构发生不兼容变化时，才升级 v22。否则保持 v21，但仍完成本版本全部健壮性工作。

建议新增：

- `scripts/save_service.gd`

`save_schema_registry.json` 至少登记字段路径、类型、默认值、范围、规范化函数、加入版本、迁移规则、是否必须和错误处理。

## 4. Save DTO 与事务规则

1. 读取分为 parse → validate → normalize DTO → commit GameState 四步。
2. parse/validate/normalize 任一步失败时，不得部分修改当前 GameState。
3. 保存先序列化 DTO，再写入同目录临时文件；写入完成并关闭后才替换正式文件。
4. 替换失败时保留旧正式文件，报告明确错误；不得留下半写 JSON 冒充成功。
5. 可保留一份 `.bak`，但备份策略、恢复顺序和清理规则必须可测试。
6. 测试使用独立 `user://test_v140_<case>.json`，不得覆盖用户真实 `savegame.json`。
7. `GameState.save_game/load_game` 公共 API 保持兼容，可内部委托 SaveService。
8. DTO 不持有 Node、Resource、Callable 或运行时对象，只包含 JSON 可序列化数据。

## 5. 必须覆盖的状态

- 48格背包、48格仓库及堆叠数量。
- 六栏独立装备、掉落等级、品质、魔魂、战魂、天魂、地魂、孔洞。
- 独立矿石品质。
- 幻兽实例 ID、等级/经验、死亡/生命、出征、合体、最多2只出征及 next ID。
- 研究所技术、产量、库存、VIP。
- learned skills、关系、军衔、爵位、日常领取日。
- 任务、五福娃、战魂谜宫、PK、领地、最终战、结局。
- 人物当前生命/体力与地图位置状态。

## 6. 边界与损坏输入

至少处理：

- 空文件、截断JSON、错误顶层类型、未知高版本。
- 背包/仓库超48格、未知物品、负数量、超大数量。
- 重复幻兽 instance ID、超过100只、超过2只出征、死亡但非法合体。
- 装备放错槽、负强化、超上限矿石品质。
- 负金币/魔石/经验/军功/功勋；超过 int64 的文本数值。
- 废弃地图 `spider_cave`、未知地图、未解锁地下层、已完成后仍停留战魂谜宫。
- 最终战字段互相矛盾、已通关但敌军 alive。
- 研究技术/产量/库存超限。

每项必须明确：拒绝整个存档、夹紧/规范化、迁移或回退地图；不能随意混用。

## 7. 自动化测试

专项至少覆盖：

1. 当前完整 v21 存档读取后状态完全一致。
2. 最小旧档按默认值迁移，不丢已有字段。
3. 如果升 v22：v21→v22→保存→再次读取完全一致；若不升版，证明保持v21的理由和 round-trip。
4. 所有第5节复杂状态 round-trip deep equality。
5. 损坏存档返回失败且 GameState 全字段保持调用前快照。
6. 临时文件写入失败/替换失败时旧存档字节不变。
7. 成功原子替换后正式文件可解析，临时文件按策略清理。
8. 未知高版本不被旧程序悄悄降级覆盖。
9. 多次保存不造成重复物品、重复幻兽或 flag 回退。

负向至少包含：

- 在 normalize 中注入部分状态后失败 → `SAVE_TRANSACTION_PARTIAL_COMMIT`。
- 截断临时文件 → `SAVE_ATOMIC_TEMP_INVALID`。
- 删除迁移默认值 → `SAVE_MIGRATION_DEFAULT_MISSING`。
- 篡改字段类型 → `SAVE_SCHEMA_TYPE_MISMATCH`。
- 保存失败后旧文件变化 → `SAVE_OLD_FILE_NOT_PRESERVED`。
- unknown future version 被接受 → `SAVE_FUTURE_VERSION_ACCEPTED`。
