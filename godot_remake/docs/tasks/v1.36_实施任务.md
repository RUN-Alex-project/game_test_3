评审角色：项目经理 / 系统工程师

版本限制：只实施 v1.36，不开始 v1.37

## 1. 版本目标

在不改变玩法、坐标、数值和地图拓扑的前提下，把当前静态 NPC、特殊怪物及剧情对象中有明确 SWF 文本证据的时间轴补成可审计、可取消、可测试的原生动画。

本版本不是“让所有人物随便动起来”。没有帧、保持次数、锚点或播放方式证据的对象必须继续使用静态原生帧，并登记为证据缺口。

## 5. 时间轴注册表结构

每项至少登记：

- `timeline_id`
- `entity_ids` / `monster_ids`
- `classification`
- `trigger`：idle、hover、dialogue、attack、hit、death、story_once 等
- `frames`：资源路径、持续时间、position offset、size、anchor
- `loop_mode`：loop、once_restore、once_hold
- `cancel_policy`
- `fallback_frame`
- `evidence_source` / `evidence_tokens`
- `implementation_path` / `test_scene`
- `evidence_gaps`

注册表不得把运行时当前值冒充 SWF 原始值。一个 sprite 被多个实体复用时必须显式登记 `reuse_of` 或共享 timeline ID。

## 6. 实现要求

1. 只有 `native_confirmed` 项允许新增帧播放。
2. 同类对象达到三个及以上时，提取可复用时间轴播放器；不得复制三份近似计时代码。
3. 播放器必须支持确定性推进：测试可直接推进到指定毫秒/帧，而不是依赖实际睡眠猜时机。
4. actor 仍使用 v1.35 的 `world_entity_id/world_action_id`；动画不得改变交互命中区域和注册表坐标。
5. 对话打开、地图切换、actor 被移除、战斗取消、目标死亡和场景退出时必须取消相关 Tween/Timer，并恢复或释放节点。
6. 一次性剧情动画必须防止重复并保留静态 fallback；不得因此新增奖励或剧情状态。
7. 不得把未知普通怪统一套用 Boss 动画，不得用镜像帧伪造缺失方向。
8. 不得通过不断创建未回收 Timer 的方式实现循环。

## 7. 自动化测试

新增：

- `tests/test_native_timeline_registry_scene.gd`
- `tests/test_native_timeline_registry_scene.tscn`

加入 `run_tests.ps1`，测试总数在 v1.35 的 50 项基础上按实际新增数量递增。

专项必须覆盖：

1. 候选对象全部被注册表分类，无漏项或重复 ID。
2. 每个 `native_confirmed` 时间轴的资源存在，证据 token 命中，implementation/test 路径存在。
3. 在 `t=0`、每个帧边界前后和循环/结束点，texture path、position、size、anchor 与注册表一致。
4. `once_restore` 结束后精确恢复原 texture/position/size；`once_hold` 停在证据指定帧。
5. 地图切换、战斗取消、actor 删除后无活动 Tween、无悬空 Timer、无失效节点访问。
6. 既有五类人物/普通怪/Boss 动画回归保持原值。

负向测试至少包含：

- 篡改 frame path → `TIMELINE_FRAME_RESOURCE_MISMATCH`。
- 篡改 duration/fps → `TIMELINE_DURATION_MISMATCH`。
- 篡改 anchor/offset → `TIMELINE_TRANSFORM_MISMATCH`。
- 删除 cancel policy → `TIMELINE_CANCEL_POLICY_MISSING`。
- 篡改 evidence token → `EVIDENCE_TOKEN_MISS`。

每项先断言变异成功，再调用与正向相同的验证器命中精确错误码。
