# v1.37 实施任务书

版本主题：技能、战斗特效、掉落与声音反馈校正  
执行角色：资深 Godot 开发工程师  
评审角色：项目经理 / 系统工程师  
发布时间：由用户正式交付本任务书时填写  
前置门禁：v1.36 已由 PM/SE 正式验收  
版本限制：只实施 v1.37，不开始 v1.38

## 1. 版本目标

建立“生产事件→视觉/文本/声音反馈→忙状态结束”的可审计顺序，让普通攻击、主动技能、受击、闪避、死亡、胜利、升级和掉落领取具有确定、无重复、可测试的反馈。

本版本只校正反馈时序，不改变伤害、成功率、掉落概率、奖励数量或技能倍率。

## 2. 当前基线

- `AudioService.SOUND_PATHS` 当前映射 18 个事件，素材目录实际有 37 段音频。
- `SceneBattleController` 已处理普通攻击、技能体力降级、怪物反击、胜负、人物死亡及原生攻击/受击动画。
- 已接入技能：被动 `fighting_spirit`，主动 `flying_slash` / `star_sword`，关系技能 `love_power`。
- 当前普通攻击直接调用 `AudioService.play("attack")`，胜利/死亡/升级等由不同脚本分散调用。
- headless 环境中 AudioService 不创建播放器，因此测试不能把“没有声音设备”误判为事件未触发。

## 4. 实现要求

1. 为 AudioService 增加可测试的事件记录或信号；headless 下仍记录事件，但不必实际播放音频。
2. 保留现有 `play(sound_name)` 兼容入口，生产代码逐步改为带事件语义的调用，不能为测试复制第二套假流程。
3. 同一逻辑事件只允许播放一次；事件 ID、session/sequence 和 dedupe key 必须可追踪。
4. 反馈顺序以 v1.36 时间轴触发点或 SWF 文本证据为准；没有证据的视觉特效不得虚构。
5. `fighting_spirit` 是被动技能，不得伪造主动施放动画；若 SWF 只有被动图标/状态，注册表明确标记。
6. 体力不足导致主动技能退化为普通攻击时，只播放实际发生的普通攻击反馈，并产生明确 `skill_failed_stamina` 事件。
7. 战斗忙状态期间，额外输入必须按证据固定为拒绝或单槽排队；不得因连续点击造成重复扣体力、重复伤害或重复音效。
8. 取消战斗、目标死亡或场景切换后，不得继续播放旧 session 的延迟反馈。
9. 掉落领取只校正文本/音效反馈；概率和物品内容留给 v1.39 审计。

## 5. 自动化测试

新增：

- `tests/test_combat_feedback_sequence_scene.gd`
- `tests/test_combat_feedback_sequence_scene.tscn`

专项使用真实 `SceneBattleController`、真实 `AudioService` 事件记录和可控时间推进，至少覆盖：

1. 普通攻击完整事件顺序及每项一次。
2. `flying_slash`、`star_sword` 成功施放的技能 ID、体力、伤害反馈与结束顺序。
3. 体力不足降级普通攻击，不重复扣体力、不重复声音。
4. 闪避路径无受击声音/受击动画，出现 dodge 反馈。
5. 怪物死亡后无反击，胜利与奖励入队顺序正确。
6. 人物死亡后无后续玩家攻击，死亡反馈一次。
7. 掉落领取成功与背包满失败的反馈不同，失败不删除队列物品。
8. 连续输入时执行任务书确定的拒绝/排队规则。
9. 取消 session 后延迟回调不产生新事件。
10. 37 段音频全部有分类，证据 token 与文件路径可验证。

负向至少包含：

- 重复相同 dedupe key → `FEEDBACK_DUPLICATE_EVENT`。
- 交换攻击/受击顺序 → `FEEDBACK_SEQUENCE_MISMATCH`。
- 未登记 sound ID → `FEEDBACK_SOUND_UNREGISTERED`。
- 被动技能伪装主动播放 → `FEEDBACK_PASSIVE_SKILL_TRIGGERED`。
- 取消后注入旧 session 事件 → `FEEDBACK_STALE_SESSION_EVENT`。
