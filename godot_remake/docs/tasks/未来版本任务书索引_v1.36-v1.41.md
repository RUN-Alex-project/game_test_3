## 1. 使用方式

本目录中的任务书已经提前写好，但**任务书存在不等于版本已经获准开工**。

用户每次只把一份任务书交给开发工程师。开发工程师必须先确认前一版本已有 PM/SE 正式验收文件，再开始当前版本。未经正式验收，不得并行开发、预做或提交下一版本内容。

交付顺序固定为：

| 版本 | 主题 | 前置版本 | 核心产物 |
|---|---|---|---|
| v1.36 | NPC、特殊怪物与剧情对象原生时间轴 | v1.35 | 时间轴证据、注册表、可取消播放器、参数化测试 |
| v1.37 | 技能、战斗特效、掉落与声音反馈 | v1.36 | 反馈事件注册表、事件顺序、声音去重、忙状态规则 |
| v1.38 | 剧情与对话分支完整性 | v1.37 | 剧情对话注册表、状态机、首次/重复/跨日/读档测试 |
| v1.39 | 原版数值与用户覆盖值双层审计 | v1.38 | 数值审计注册表、用户覆盖冻结、forced-roll 边界测试 |
| v1.40 | 存档架构与边界场景加固（条件性 v22） | v1.39 | Save DTO、原子写入、迁移与损坏存档测试 |
| v1.41 | 发布候选版与人工验收包 | v1.40 | Windows 构建、长流程测试、纯文字试玩清单、校验清单 |

v1.41 是当前已规划路线的终点。v1.42 及以后不在本轮授权范围内，必须根据 v1.41 试玩结果另行规划。

## 2. 全局发布门禁

每个版本均遵守以下规则：

1. 开发报告不能作为完成证明；PM/SE必须独立检查代码、数据、证据、测试和报告。
2. `run_tests.ps1` 中每个自动化场景必须有 `^PASS ` 完成标记、进程退出码 0，且日志无有效 `SCRIPT ERROR` / `ERROR` / `FAILED`。
3. 全量测试必须包含主场景冒烟；新增专项测试后，测试总数使用实际数量，不得从未来任务书硬猜。
4. 负向测试必须先证明变异实际发生，再证明与正向相同的验证器命中精确错误码。
5. 不得以源码字符串搜索、未使用变量、空 fixture、静默 `if found` 或仅检查“非空”冒充真实路径验证。
6. SWF 未确认字段写 `UNCONFIRMED` / `evidence_gap`，不得凭截图、对称性、名称或经验猜测。
7. 用户覆盖值优先于“还原原版”；只有用户明确批准，才允许改变已冻结覆盖值。
8. 不得重新接入 legacy `MapPanel` / `BattlePanel`；地图移动继续使用场景边缘入口，战斗继续发生在地图演员上。
9. 每版只修改本任务书允许的范围。发现跨版本问题时登记缺口并交 PM/SE 决策，不得顺手扩大范围。
10. 完成后停止，等待 PM/SE 正式签署；不得自行开始下一版。

## 3. 无图像工程师的证据规则

证据优先级：

1. SWF ActionScript、PlaceObject、sprite/shape 定义和根时间轴矩阵的文本化导出。
2. 已验证的 `docs/*.json` 注册表和 `docs/evidence/*.txt` token。
3. 生产代码中的实际资源引用、坐标、状态转换和 dispatcher。
4. 自动化测试中的精确断言。
5. 历史版本文档仅用于定位，不能单独证明当前实现正确。

每项证据必须能定位到文件、角色/sprite、token 或命令。截图可供人类辅助检查，但不得作为无图像模型的唯一验收材料。

## 4. 冻结的用户覆盖值

以下值在 v1.39 完成审计前也必须保持不变：

- 初始金币与魔石：各 `99,999,999,999`。
- 杂货商/收藏家出售标题每次增加对应货币 `99,999,999,999`，仅在有符号 64 位整数溢出前停止。
- 人物经验倍率：10 倍；幻兽经验不误乘人物倍率。
- Boss 军功倍率：10 倍；普通怪军功倍率：1 倍。
- 品质、魔魂成功率：100%；战魂晶石成功率：50%。
- 战魂按最低魂等级每级提供 10% 战斗力加成。
- 99/999 玫瑰分别增加 50/250 好感。
- 幻兽研究所技术上限 300，产量任务每次 +2，日产量上限 6。
- 蜘蛛技能书基础概率保持当前双倍规则；蜘蛛王后及 60 级以上原生 Boss 的增强月光宝盒保持 50% 规则。
- v1.34 已登记的 75,000,000 金币 VIP 便捷档与日常官 intentional divergence 不得被“原版还原”误删。
