# v1.35 整改任务03

任务主题：消除动态矩阵同错同过、补齐真实action结果和修复不实交付  
执行角色：资深开发工程师  
评审角色：项目经理 / 系统工程师  
前置状态：v1.35整改02复验不通过  
版本限制：只修整改03，不开始v1.36

## 1. 核心原则

本任务不再接受：

- 用case数量代替状态覆盖。
- 用空fixture代替动态状态。
- 用测试侧复刻生产条件来生成“期望结果”。
- 用源码字符串搜索代替dispatcher验证。
- 用没有assert的代码宣称状态差已测试。
- 用普通字典变异冒充指定runtime metadata或scenario保护分支。

每项完成声明必须对应实际执行的断言和可核验状态差。

## 2. 独立动态期望

### 2.1 scenario必须登记独立期望

每个dynamic scenario至少登记：

- scenario_id。
- map_id。
- fixture。
- `expected_dynamic_present`。
- `expected_dynamic_absent`。

测试可以把注册表always实体与 `expected_dynamic_present`合并为完整期望集合，但不得再通过 `_condition_active()`读取同一GameState自动推导动态期望。

对该地图所有条件实体：

- 必须恰好出现在present或absent之一。
- 不能两边都没有。
- 不能同时出现在两边。

运行时集合必须与：

`always实体 + expected_dynamic_present`

完全相等。

### 2.2 必须补齐的状态

#### PK

对60、100、130三张赛场分别覆盖：

- 未报名/未开始。
- active且对应Boss出现。
- 当日已参加并已结束/击败，Boss不再出现。

fixture至少支持 `pk_race_active`、`last_pk_race_day`、current_day和组别所需level/map。

#### 最终战

fixture必须支持完整 `demon_campaign`。

对六种敌人分别覆盖：

- alive时出现。
- 对应alive字段为false后缺失。

另覆盖 `game_won=true`后所有最终战敌人不再生成。

#### 领地

领地挑战者不是单纯 `_apply_current_map()`常驻实体，必须使用带步骤的action scenario或专用数据驱动器。

六张领地地图至少逐图覆盖：

- 爵位不足：挑战失败且无临时挑战者。
- 资格满足：挑战可开始。
- 开始挑战后：正确 `battle:territory_*_guard`临时演员出现并进入正确session。
- 已占领：owned_territory正确，报名官对话状态正确。

测试必须比较临时挑战者的ID、kind、action、asset、position和size，并在结算后验证移除。

#### 战魂、五福娃和其他状态

- 战魂增加秘密已完成/谜宫不活动后的缺失态。
- 五福娃16个使者case继续保留present/absent独立期望。
- 草原战斗、草原2领奖、树心城待交付/已完成必须登记明确期望；如果地图内演员始终存在，应如实说明“地图可达条件控制而非演员条件”，并测试相应入口条件，不得伪称演员动态。
- 皇宫、探险家继续覆盖present/absent。

### 2.3 动态覆盖审计

测试必须断言：

- 每个条件实体至少有一个present case和一个absent case。
- 领地六图每图都有四类状态结果。
- 最终战六敌人每个都有alive/dead。
- PK三组每组都有inactive/active/finished。
- scenario ID唯一。
- fixture非空要求按场景类型执行；default场景不能计入动态状态完成数。

## 3. 完整GameState隔离

快照、恢复和fixture至少增加：

- level。
- magic_stones。
- inventory及矿点/抽奖会改动的相关资源。
- demon_campaign。
- owned_territory。
- pending_territory_challenge。
- last_territory_challenge_day。
- last_territory_reward_day。
- nobility_merit。
- last_pk_race_day。
- current_day。
- story_flags。
- fuwa_event。
- war_soul字段。
- pk_race_active。

每个dynamic case和action case：

1. 保存快照。
2. 应用明确默认状态。
3. 应用fixture。
4. 执行。
5. 断言结果。
6. 恢复快照。
7. 断言关键字段确实恢复。

不得依赖独立Godot进程退出掩盖测试内污染。

## 4. 真实action支持与12类状态差

### 4.1 禁止源码字符串搜索

删除：

- `main_src_text`。
- `zzz_unknown_action in source`。
- 任何以源码字符串出现作为action supported证明的断言。

建立真实dispatcher支持机制。允许：

- 在活动主场景增加只读 `_world_action_route(action_id)`，并让实际dispatcher和测试共同使用。
- 或由真实dispatcher返回明确supported/unsupported结果。

未知action必须实际传入dispatcher并得到 `UNSUPPORTED_ACTION`或明确等价结果。

### 4.2 全量action

注册表所有非空action ID必须得到明确route分类：

- npc_dialogue。
- panel/dialogue action。
- battle。
- mine。
- lottery。
- territory。
- war_soul。
- travel。

未知route令测试失败。

### 4.3 代表性12类补正

- 普通NPC：断言dialogue visible及speaker为目标NPC。
- 商店：通过真实dialogue action打开正确shop。
- 仓库：通过 `_handle_dialogue_action("warehouse")`或实际等价dispatcher，不得直接toggle。
- 研究所：真实action打开正确panel。
- 普通怪和Boss：断言session及monster ID。
- 领地：断言对话属于正确地图，并补真实挑战者action。
- 矿点：比较挖矿前后inventory/矿石数量或明确状态结果；必须有assert。
- 抽奖：比较魔石及奖励状态，并恢复。
- 战魂：箱子揭示守卫后，实际点击守卫并断言正确battle session。
- 边缘出口：通过按钮signal改变地图。
- NPC传送：通过实际dialogue action改变地图。

## 5. 出口运行时字段与metadata

保留48出口evidence-gap分类，同时增加明确的runtime字段，例如：

- runtime_required_level。
- runtime_availability_rule。

`NativeExitButton` metadata至少增加：

- world_entity_id。
- world_current_map。
- world_direction。
- world_target_map。
- world_action_route。
- world_required_level。

验证器比较：

- 所有上述metadata。
- position/size。
- disabled与当前can_enter_map结果。
- runtime_required_level与 `GameState.map_entry_required_level()`。
- action_route。

不得只断言注册表action_route等于常量。

## 6. 边界补正

恢复并强制：

- x >= 0。
- y >= 0。
- `x + width <= 700`。
- bottom <= 512，除非登记runtime overlap exception。
- 有exception仍必须bottom <= 550。

负向测试增加一个右侧越界实体，必须返回 `OVERLAP_BEYOND_CANVAS`。

## 7. gap字段覆盖

现有 `(map_id, object_id)`复合键保留。

验证器进一步检查：

- 每个evidence_status=unconfirmed字段均被对应gap.field覆盖。
- 48出口availability/required_level均映射到对应gap。
- 不得只验证对象出现在任意gap中。

## 8. 九项负向验证纠正

保留有效项并纠正：

1. 缺少实体 → `ENTITY_SET_MISSING`。
2. 多余实体 → `ENTITY_SET_EXTRA`。
3. kind/action不符 → 对应mismatch。
4. 出口字段不符 → 对应exit mismatch。
5. 修改一个真实scenario的 `expected_dynamic_present/absent`，执行scenario runner并失败。
6. 临时移除实际装饰节点的 `world_entity_id`，重新snapshot后失败，再恢复metadata。
7. 把未知action传入真实dispatcher，返回 `UNSUPPORTED_ACTION`。
8. 移除Boss exception → `OVERLAP_EXCEPTION_MISSING`。
9. token不存在 → `EVIDENCE_TOKEN_MISS`。

追加右侧越界负向可作为第6节专用保护，不计入九项也可。
