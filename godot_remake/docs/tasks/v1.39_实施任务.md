# v1.39 实施任务书

版本主题：原版数值与用户覆盖值双层审计  
执行角色：资深 Godot 开发工程师 / 数据审计工程师  
评审角色：项目经理 / 系统工程师  
发布时间：由用户正式交付本任务书时填写  
前置门禁：v1.38 已由 PM/SE 正式验收  
版本限制：只实施 v1.39，不开始 v1.40

## 1. 版本目标

建立一份可追溯、可机检的数值真值表，明确区分：

1. 能从 SWF 文本证据确认的原始值。
2. 用户明确要求的覆盖值。
3. 当前 Godot 实际生效值。
4. 暂时无法确认的 evidence gap。

本版本的核心不是“把数值改回原版”，而是防止后续还原工作误删用户修改，并找出重复倍率、魔法数字漂移和边界比较错误。

## 4. 必须审计的领域

### 4.1 人物与幻兽经验

- 人物经验倍率 10 倍，只应用一次。
- 怪物基础经验、任务经验、PK经验、研究所任务经验逐入口检查。
- 幻兽获得怪物基础经验，不误乘人物 10 倍。
- 经验球容量、训练与幻化等级限制保持当前规则。

### 4.2 军功、功勋、军衔与爵位

- Boss 军功 10 倍，普通怪 1 倍。
- 雪域精英、地下城 Boss、PK、最终战、日常任务分别审计。
- 军衔/爵位门槛与战斗力加成以 `data/ranks.json` 为当前权威源。
- 750,000 金币换 1 功勋；75,000,000 便捷档作为 convenience override 保留。
- 日常官“魔魂晶石500/灵魂王2000”继续标 intentional divergence，不擅自改回原版文本值。

### 4.3 商人无限货币

- 初始金币、魔石均为 `99_999_999_999`。
- 杂货商/收藏家出售标题每次增加对应货币 `99_999_999_999`。
- 仅在超过 `9_223_372_036_854_775_807` 前拒绝继续增加；不得加回 999,999,999 的旧上限。

### 4.4 装备养成与关系

- 品质、魔魂成功率 1.0。
- 战魂晶石成功率 0.5，比较符号为 `<`。
- 战魂每个最低魂等级提供 10% 战斗力加成。
- 天魂/地魂上限和公式保持当前实现，原版无法确认项登记 gap。
- 99/999 玫瑰分别 +50/+250 好感。

### 4.5 幻兽与研究所

- 技术等级初始10、解锁20、上限300。
- 产量任务每次 +2，日产量上限6，库存上限100。
- 资助成本、售价、品质公式、周增长逐项登记。
- 幻化机制本版本只审计，不改变。

### 4.6 掉落与概率

- 蜘蛛技能书当前基础概率：30%/50%/60%，再应用原生幸运倍率；登记为用户要求的双倍规则。
- 蜘蛛王后高级技能书：40%/40%/20%，并审计灵魂类掉落。
- 蜘蛛王后增强月光宝盒固定50%。
- 60级以上原生Boss增强月光宝盒固定50%；60级及以下保持普通月光宝盒路径。
- 战魂解锁后的Boss首个晶石分支使用当前 `>0.50` 语义，必须单独记录，不能误写成通用 `<0.50`。
- forced-roll 边界必须测试 `p-ε`、`p`、`p+ε`，并记录 `<` / `<=` / `>` 的实际语义。

## 5. 实现与去重规则

1. 先完成注册表和一致性测试，再决定是否迁移魔法数字。
2. 只有同一 effective value 在两个生产位置可能漂移时，才允许迁移到 JSON/服务唯一源。
3. 迁移前后必须用代表输入证明输出完全相同。
4. 不得以“原版值更合理”为理由覆盖用户值。
5. 发现 Godot 当前值与已签署用户值冲突时，停止该项并提交 PM/SE；不得自行选边。
6. 概率测试使用 forced rolls，不用大样本随机统计代替边界证明。

## 6. 自动化测试

新增：

- `tests/test_value_audit_registry_scene.gd`
- `tests/test_value_audit_registry_scene.tscn`

专项至少覆盖：

1. 注册表每项来源、实现和测试路径存在，token 命中。
2. 每个 `effective_value` 与生产配置/函数结果一致。
3. 用户覆盖清单完整，删除任一项会失败。
4. 人物经验各入口只乘一次10倍，幻兽经验不乘。
5. Boss/普通怪军功倍率分离。
6. 商人货币可连续增加并只在 int64 溢出前失败。
7. 品质/魔魂必成、战魂50%、玫瑰、研究所关键值精确匹配。
8. 蜘蛛、王后、原生Boss的 forced-roll 边界和掉落集合。
9. JSON 与服务中不存在未登记的重复权威值。

负向至少包含：

- 删除用户覆盖 → `USER_OVERRIDE_MISSING`。
- effective value 与配置不一致 → `VALUE_EFFECTIVE_MISMATCH`。
- 人物经验重复乘10 → `VALUE_MULTIPLIER_APPLIED_TWICE`。
- 普通怪误用Boss军功倍率 → `VALUE_SCOPE_MISMATCH`。
- 把 `<0.50` 改成 `<=0.50` → `VALUE_PROBABILITY_BOUNDARY_MISMATCH`。
- 生产代码存在未登记魔法数字 → `VALUE_UNREGISTERED_MAGIC_NUMBER`。
