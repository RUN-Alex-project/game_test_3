# v1.33 整改任务单 01

执行角色：资深开发工程师  
评审角色：项目经理 / 系统工程师  
优先级：阻断 v1.34  
工作类型：测试执行器加固、证据定位修复和文档一致性修正

## 1. 任务目标

保留v1.33已经通过的旧面板运行时退役实现，只修复以下三个交付问题：

1. `run_tests.ps1` 没有要求每个测试输出明确PASS，仍可能假通过。
2. v1.33删除 `main_original.gd` 代码后，注册表54项数字行号证据已漂移。
3. `开发进度.md` 顶部测试总数仍写47。

本整改不是v1.34，不修改玩法或存档，不增加测试场景数量。

## 2. 事实依据

PM/SE独立复验：

- 使用额外循环逐场景要求日志出现 `^PASS `：48/48通过。
- 主场景冒烟：退出码0，非忽略错误0。
- 说明当前v1.33功能实现有效。

但当前 `run_tests.ps1`：

- 只检查退出码和脚本错误。
- 未读取PASS完成标记。
- 在最终判定前删除场景日志。

注册表检查：

- 55项资源证据包含 `main_original:<数字行号>`。
- 仅1项当前仍直接命中对应 `image_id`。
- 54项已随v1.33删行而漂移。

## 3. 必须修改

### 3.1 加固 `run_tests.ps1`

对每个 `$scene`：

1. 在删除 `$logFile` 前读取：

```powershell
$passMarks = @(Select-String -LiteralPath $logFile -Pattern "^PASS " -ErrorAction SilentlyContinue)
```

2. 以下任一条件成立都必须失败：

- `$process.ExitCode -ne 0`
- 存在非忽略 `$scriptErrors`
- `$passMarks.Count -eq 0`

3. 失败信息必须区分“退出码/脚本错误/缺少PASS完成标记”。
4. 失败时至少把日志路径或关键日志内容留给执行者；不能先无条件删除唯一诊断。
5. 成功时可以删除临时日志。
6. 保留 `--quit-after 1200` 作为测试上限。
7. 主场景冒烟不是断言测试，不要求PASS行；继续检查退出码和错误即可。

不得只把1200继续提高到更大的数字来代替完成标记。

### 3.2 修复注册表稳定定位

修改 `docs/swf_evidence_registry.json`：

1. 对UI/动画继续以 `godot_file` + `godot_symbol` 作为主要定位。
2. 对资源项增加稳定、机器可验证的定位，推荐字段：

```json
"source_refs": [
  {"path": "res://scripts/main_original.gd", "token": "image_0038"}
]
```

3. 一个资源有多个活动/legacy/data来源时，可登记多个 `source_refs`。
4. `path` 必须是存在的Godot资源路径；`token` 必须在该文件文本中存在。
5. 删除、更新或降级已经漂移的 `main_original:<数字行号>`，不得继续把失效行号当作权威定位。
6. 不修改SWF角色号、坐标、尺寸、色值、scope和用户覆盖值。

如果执行者选择更新精确行号而不是引入 `source_refs`，必须同时增加自动测试，证明每个数字定位当前行/范围包含对应资源token；并说明如何防止下一次删行后再次整体漂移。PM/SE优先接受路径+token方案。

### 3.3 加固注册表专项测试

在现有 `tests/test_swf_evidence_registry_scene.gd` 中增加：

1. 如果资源项具有 `source_refs`，每个ref必须含非空 `path` 和 `token`。
2. `FileAccess.file_exists(path)` 必须为true。
3. 打开path后必须能找到token。
4. 对 `scope=active` 或 `active+legacy` 的资源，至少有一个非legacy活动来源ref，或由现有活动引用扫描证明。
5. 对仍保留数字行号的机器可验证引用，必须验证行/范围实际命中对应token。

不得新增第49个测试场景；继续使用现有注册表专项测试。

### 3.4 修正文档

1. `开发进度.md` 顶部“最近一次回归”由47改为48。
2. `版本改动.md` 和 `开发进度.md` 中关于1200帧的描述改为：
   - 1200帧是超时上限。
   - runner同时要求每个自动化场景输出PASS完成标记。
3. 在v1.33条目追加本次整改，不创建v1.34。

## 5. 验证要求

专项：

- `test_swf_evidence_registry_scene.tscn`
- `test_no_legacy_panels_scene.tscn`
- `test_scene_battle_scene.tscn`
