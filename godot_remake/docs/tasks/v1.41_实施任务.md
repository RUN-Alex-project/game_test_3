# v1.41 实施任务书

版本主题：发布候选版与人工验收包  
执行角色：资深 Godot 开发工程师 / 发布工程师  
评审角色：项目经理 / 系统工程师 / 用户  
发布时间：由用户正式交付本任务书时填写  
前置门禁：v1.40 已由 PM/SE 正式验收  
版本限制：v1.41 是当前路线的发布候选终点，不自动规划 v1.42

## 1. 版本目标

形成用户可以连续试玩、可复现验证、可回退定位问题的 Windows 发布候选包。该版本以稳定、可试玩和验收材料完整为目标，不再新增玩法或重构核心系统。

若发现阻断性缺陷，应登记并回到对应责任版本整改；不得在 RC 阶段顺手加入新系统。

## 2. 发布前冻结

开始本任务后冻结：

- 玩法数值与用户覆盖值。
- 地图拓扑、演员、对话和剧情状态机。
- 存档 schema 与迁移规则。
- 原生时间轴、战斗反馈和音频映射。

只允许修复可证明的发布阻断缺陷。每个修复必须有专项回归和 PM/SE 审批。

## 3. Windows 构建

当前仓库没有 `export_presets.cfg`，本版本需要建立明确的 Windows Desktop 导出预设。

输出建议：

`artifacts/releases/v1.41/`

至少包含：

- `魔域1.03_v1.41.exe`
- 如非嵌入式导出则包含对应 `.pck`
- `build_manifest.json`
- `SHA256SUMS.txt`
- `试玩验收清单_v1.41.md`
- `已知问题_v1.41.md`
- `版本改动.md` 副本或发布摘要

构建名称只使用简洁版本号，不把每项修改写入文件名。不得打包用户的 `savegame.json`、测试临时存档、私有日志或无关开发缓存。

## 4. 自动化测试与长流程

新增：

- `tests/test_release_candidate_scene.gd`
- `tests/test_release_candidate_scene.tscn`
- 必要时新增 `run_release_acceptance.ps1`

除全部既有自动化外，至少覆盖以下长流程：

1. 新游戏启动、基础UI、商人、仓库、装备、幻兽和存档。
2. 从新游戏推进到地下城三层救王、国王回宫。
3. 最终战六类敌人、跨日复活、主帅、魔的能量与结局。
4. 五福娃完整流程。
5. 战魂秘密完整流程。
6. PK三组中的代表组及当天重复限制。
7. 六图领地中的最低/最高门槛代表流程。
8. 背包满、仓库满、掉落未领取、拖动交换和交易回滚。
9. 人物死亡、幻兽死亡/合体、地图切换和战斗取消。
10. v1.40 支持的旧存档迁移、保存、重启再读取。

长流程不得靠直接写最终 flag 冒充完成；可以用已公开生产 API 缩短重复战斗，但必须保留真实状态转换。

## 5. 纯文字试玩验收清单

`试玩验收清单_v1.41.md` 必须允许不看源码的用户按步骤试玩，至少列出：

- 28张地图的到达方式、入口门槛、主要NPC/怪物和退出方向。
- 背包、仓库、商店、装备、精炼、幻兽、技能、研究所、任务簿的操作步骤。
- 所有关键NPC：杂货商、收藏家、仓库、锻造师、研究所、元帅、首相、国王、公主、侍女、日常官、PK官、抽奖官、五福娃使者、探险家。
- 地下城、五福娃、PK、战魂、领地、最终战和结局的前置、操作与预期状态差。
- 用户覆盖值的可观察验证：无限货币、10倍经验、Boss 10倍军功、必成/50%、玫瑰、研究所、掉落规则。
- 存档、退出、重启和旧档迁移步骤。

每一步写“前置状态→操作→预期界面/资源/flag变化→失败时记录信息”。不得只写“功能正常”。

## 6. 人工视觉检查

人工检查不是无图像模型的自动验收替代，但发布前必须提供清单：

- 700×550布局、顶部HUD、底栏、地图边缘入口。
- 背包/仓库/三套商店/对话/装备/幻兽/技能/精炼/研究所窗口。
- 常见分辨率缩放下的遮挡、字体、命中区。
- 原生动画锚点、闪帧、切图残留。
- 战斗反馈、伤害文本、掉落文本、声音重复。

可以附截图或视频供用户检查，但自动验收仍以文本证据和测试为主。

## 7. RC 健康检查

专项必须验证：

- 导出预设存在且指向正确主场景。
- 构建产物存在、非零、hash与manifest一致。
- 构建目录不含存档、临时日志和测试fixture。
- 可执行文件启动后进入主场景，无脚本错误。
- 新游戏与旧档各完成一次启动/保存/重启。
- 全量测试每项有 PASS，主场景冒烟通过。
- 纯文字验收清单覆盖28图和关键系统，无空占位。
- `已知问题` 中每项有严重级别、复现步骤、是否阻断与后续决定。

负向至少包含：

- manifest hash不符 → `RC_ARTIFACT_HASH_MISMATCH`。
- 构建包含 `savegame.json` → `RC_PRIVATE_SAVE_INCLUDED`。
- 清单漏地图/系统 → `RC_CHECKLIST_COVERAGE_MISSING`。
- 可执行启动日志含脚本错误 → `RC_SMOKE_SCRIPT_ERROR`。
- 长流程通过直接写终态字段 → `RC_FLOW_BYPASSED_PRODUCTION_PATH`。

## 8. 发布阻断标准

以下任一存在即不得签署：

- 主线无法从新游戏走到结局。
- 物品拖动、交易或存档造成物品消失。
- 合法旧档无法迁移或保存破坏旧档。
- 战斗卡死、输入永久锁定、切图残留会话。
- 关键NPC或地图入口不可达。
- 用户覆盖值回退。
- 自动化假通过、缺PASS或报告与实际产物不一致。

非阻断视觉差异可登记，但不得把 evidence gap 写成已完全还原。

## 9. 允许修改

- `export_presets.cfg`
- 发布脚本、RC专项测试、纯文字清单和构建manifest
- 经PM/SE批准且有复现测试的阻断修复
- README、开发进度、版本改动和已知问题

## 10. 禁止修改

- 新玩法、新地图、新数值、新剧情
- 无专项测试的大规模重构
- 为赶进度跳过旧档、背包满、死亡或长流程
- 删除 evidence gap 或夸大原版还原度
- 自动开始 v1.42
