二、引用链分析方法（整改04）
================================================================================

建立 bitmap->shape fill->sprite 嵌套->根 placement 引用链:
  1. find_swf_bitmap_shapes: bitmap X -> shape Y（fill type 0x40-0x43 引用 X）
  2. find_swf_character_parents: shape Y -> 放置 Y 的 sprite Z（含根时间轴）
  3. _v136_matrices/_v136_classify: 每帧 PlaceObject2 的 character + 完整 matrix(translate+scale+rotate) + ColorTransform 实际参数
  4. _v136_removecheck/_v136_tagscan: RemoveObject2（深度删除）帧序；tag4/tag5 全文件为 0
  5. 递归: 从 shape 出发经所有 wrapper sprite 直到根时间轴

视觉变化判定（任一触发即非静态，按帧序显示列表状态机: 保持/替换/删除）:
  - char_swap: 某 depth 跨帧放置 >1 个不同 character（替换）
  - translate: 后续 HasMatrix translate 与初始不同
  - scale_rotate: 后续 HasMatrix scale/rotate 与初始不同
  - color: 任意帧 HasColorTransform（解析实际 CXFORM 参数，非仅标志位）
  - remove: 对象在 sprite 时间轴内放置后被 RemoveObject2 删除（帧序判定: 仅当该 depth 此前存在对象）

专项用例 image_1156->shape1157->sprite1158->sprite1159:
  bitmap1156 -> shape1157(fill0引用bitmap1156) -> sprite1158(1帧,放置shape1157@(0,0))
  -> sprite1159(3帧: frame1放置sprite1158@(0,0); frame2-3 flags=0x09=Move+HasColorTransform, 无character, translate(0,0))
  -> sprite1186(3帧,同模式) -> 根时间轴frame12放置sprite1159
  sprite1159 frame2/3 ColorTransform 实际参数（CXFORM 解析，独立实测）:
    frame2: add=[77,77,77,0]（RGB 各 +77，悬停变亮）
    frame3: add=[38,38,38,0]（RGB 各 +38）
  sprite1159 frame1 DoAction: onRelease/onRollOver/onRollOut/指向NPC.wav（鼠标交互逻辑）
  结论: sprite1159 多帧且帧2/3 有 ColorTransform 悬停色变（实际参数非零）-> "视觉不变"不成立
        -> grocery 为 evidence_gap（色变是交互效果而非bitmap帧动画，remake 用静态bitmap未实现）

根时间轴 RemoveObject2 语义（场景状态机，如实记录，整改07 算法升级）:
  根时间轴 285 个 RemoveObject2 分布在帧3-38 的部分帧（帧13=29个、帧38=58个清场；
  帧7、帧37 无 RemoveObject2，并非每帧清空重建）
  -> 根时间轴的 remove 是场景状态切换机制（gotoAndStop 目标帧需 ActionScript 审计），
     不构成对象自身动画证据；swf_parser.gd 按原始 tag 顺序事件流（root_events）模拟
     depth->当前 character 显示列表：同一 depth 被其他角色替换后再删除的旧角色
     **不**算被移除（frame5 char100->depth7、frame6 char200->depth7、frame9 remove：
     char100=false、char200=true）。
  统计（整改08，独立可复现，与 PM/SE 独立模拟完全一致）:
    根时间轴唯一放置角色 186 个；事件流状态机判定被删除 149 个。
    算法语义：place 且 HasCharacter=true 更新 depth 当前角色；place 且 HasCharacter=false
    （Move 更新）不覆盖当前角色；remove 删除 depth 当前角色。
    旧缺陷对照：仅比帧号=176 误判（10 字符已固化）；"历史上出现"=176 误判（18 字符固化）；
    Move 覆盖当前角色=146 漏判（PM 点名 787/925/1228 已固化为 true——这正是整改07 的
    146 与 PM 149 的差异根源，Move 修复后 149 与 PM 完全一致）。
    PM 点名 387/1067/1092/1096/1176/1227/1237/1298 等 18 字符（替换后才删除）已固化为 false 断言。
  实例: shape1178(marshal) 根放置 frame13 depth7，frame14 RemoveObject2(depth7) 移除（depth 匹配）。
        marshal 分类保持 static_native 的依据 = bitmap/shape/wrapper 无自身动画；
        根时间轴"出现→消失"属场景状态机，需 gotoAndStop 审计确认常驻帧（证据缺口）。
