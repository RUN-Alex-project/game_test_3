# 原版《魔域 1.03》真实地图连接表 — 反编译取证与差异清单

本文件只做取证，不修改任何游戏数据。所有结论都必须能回指到 SWF 里的具体 tag / 帧 / 字节偏移。

- 取证对象：`魔域1.03_v9.swf`
- SHA-256：`5c9d0df690f2921d6bbe01e896e59a5e1b0b7a16c7f985058506cf6d762ee1e6`
- 文件大小：2,845,315 字节（CWS/zlib，SWF version 8，根时间轴 38 帧）
- 反汇编工具：`godot_remake/tools/swf_as2_dump.py`（纯标准库）
- 结构化产物：`godot_remake/docs/evidence/native_map_links.json`
- 对照目标：`godot_remake/data/maps.json`（本轮不修改）

## 0. 结论摘要

1. 原版**没有地图连接表**。每张地图的每个出口，都是同一个「出口箭头」影片剪辑（character 1071）的一个实例；实例的 `onClipEvent(load)` 把目标地图名写进实例变量 `map`，剪辑自身的 `onRelease` 执行 `_root.nowmap = map; _root.gotoAndStop(map)`。
2. 全片共 **41 个出口箭头实例**，分布在 23 个根帧上。因为 Flash 的显示列表跨帧保留，另有 4 个帧继承了更早帧放置且未被删除的箭头，所以**实际生效的出口边共 45 条**。
3. 任务书里给出的变量含义有两条是错的：`nextmap` 不是「下一张地图」，而是**布尔开关**（是否允许切图）；`owermap` 不是「上一张地图」，而是**玩家当前占领/保护的地图名**（ownermap 的拼写错误）。`returnmap` 也不是变量，是根时间轴上的一个**函数**。详见第 3 节。
4. 世界结构是**链式 + 两条回枢纽的捷径**，不是枢纽放射结构。v1.41 试玩清单里「迷梦沼泽 / 冰宫 / 火山 / 深渊迷宫 = 卡萨诺城出口」这 4 条说法与原版不符。
5. 与现有 `data/maps.json` 相比：45 条原版边里 41 条能对上，**原版有而现有没有 4 条**，**现有有而原版没有 8 条**（其中 1 条是行为等价、1 条是重制版原创地图）。

## 1. 取证方法与可复现命令

```
python godot_remake/tools/swf_as2_dump.py <魔域1.03_v9.swf> \
    --out disasm.txt --json events.json \
    --map-links godot_remake/docs/evidence/native_map_links.json
```

工具做了 7 件事：解 CWS 容器 → 跳 FrameRect → 遍历 tag 并维护 ShowFrame 帧计数 → 把 FrameLabel 绑到帧号 → 递归进入 DefineSprite → 从 DoAction / DoInitAction / DefineButton / DefineButton2 / PlaceObject2 的 ClipActions 五种载体收集字节码 → 反汇编并跑一个抽象栈解释器输出结构化事件。

覆盖量（可复现的计数，用于自校验）：

| 项目 | 数量 |
|---|---|
| 根时间轴 DoAction | 37 个，26,225 字节 |
| 全文件 DoAction（含 sprite 内） | 408 个，308,131 字节 |
| PlaceObject2 ClipActions | 344 个 |
| DefineButton2 条件动作 | 65 个 |
| 合计反汇编动作块 | 817 个，352,888 字节 |

根 DoAction 的 37 个 / 26,225 字节与任务书给出的普查数字**逐字节吻合**，可作为容器解析正确性的独立佐证。

### 1.1 两项自校验

1. **可复现**：同一个 SWF 跑两次，`native_map_links.json` 的 SHA-256 完全一致。
2. **跨版本一致**：对仓库里 9 个 SWF 中最旧的 `魔域1.03_v1.swf`（SHA-256 `74bf0bd3...`，2,845,277 字节）跑同一条命令，得到的**出口边集合与门槛规则与 v9 完全相同**（45 条边、6 条门槛、0 告警），差异只有字节偏移（v1/v9 相差 38 字节，导致偏移整体平移）。也就是说 v1→v9 这 9 个版本改的不是地图连接，本文件的连接表对整个 1.03 系列都成立。

## 2. 原版切图机制（关键发现）

出口箭头剪辑 = **character 1071**。它的帧 1 脚本在 `tag#4948`（sprite1071 frame 1，1,699 字节），常量池 48 项。核心是 `this.onRelease`（`0x24ABC6` 起，code_size=705）：

```
// tag#4948 @0x24AE1E 起
if (_root.nextmap) {              // 0x24AE1E  Push r1,'nextmap'; GetMember; Not; If +97
    _root.nowmap = map;           // 0x24AE2C  Push r1,'nowmap','map'; GetVariable; SetMember
    _root.minmap.updata();        // 0x24AE37  （字节码里的 0.0 是 CallMethod 的实参个数）
    _root.talk.closeme();         // 0x24AE4F
    _root.CloseAll();             // 0x24AE67
    _root.gotoAndStop(map);       // 0x24AE79  Push 'map'; GetVariable; Push 1; ... CallMethod
}
```

目标地图名不在这段代码里，而在**每个实例自己的 `onClipEvent(load)`** 里。例如卡萨诺城通往戈壁的那个箭头：

```
--- tag#5409 ClipActions  root frame 12  label=卡萨诺城  character=1071  depth=36  clip_flags=0x00000001 ---
270480: Push 'map', '戈壁'
270490: SetVariable
270491: End
```

`clip_flags=0x00000001` 即 `ClipEventLoad`。所以「一个 PlaceObject2(character=1071) + 一段 onClipEvent(load) 写 map」= 一条地图连接边。这就是原版连接表的**唯一**数据来源。

### 2.1 必须模拟显示列表，否则会漏边

Flash 里某一帧的显示列表，是从第 1 帧到该帧的全部 PlaceObject2 / RemoveObject2 累积出来的；放上去没被删的对象会一直留在后面的帧上。所以有 4 条边在自己的帧上**没有** PlaceObject2，是继承来的：

| 帧 | 地图 | 继承的箭头 | 来源帧 | 目标 |
|---|---|---|---|---|
| 15 | 抽奖房 | depth 27 | 14（后花园） | 皇宫 |
| 29 | 地下城2层 | depth 27 | 28（地下城1层） | 卡萨诺城 |
| 32 | PK赛场2层 | depth 2 | 31（PK赛场1层） | 卡萨诺城 |
| 33 | PK赛场3层 | depth 2 | 31（PK赛场1层） | 卡萨诺城 |

工具的 `simulate_root_display()` 按 tag 顺序重放 PlaceObject2/RemoveObject2 得到每帧真实显示列表，这 4 条边才被找出来。若只统计 PlaceObject2 会得到 41 条，漏掉这 4 条。

## 3. 变量语义订正（有证据，推翻任务书的两条假设）

全片对这 4 个符号的引用已穷举（工具扫描全部 817 个动作块）：

| 符号 | 任务书假设 | 字节码实证 | 出现位置（全部） |
|---|---|---|---|
| `nowmap` | 当前地图 | **正确**。字符串，唯一承载「我在哪张图」的变量 | 16 个块 |
| `nextmap` | 下一张 | **错误**。布尔开关，唯一赋值是 `nextmap = true`；用法是 `if (_root.nextmap) { 切图 }`。全片从未被赋成地图名 | 仅 3 处：`tag#2274 @0x1A4B18` 初始化 true；`tag#2445` 存/读档持久化；`tag#4948 @0x24AE1E` 切图前的门禁判断 |
| `owermap` | 上一张 | **错误**。字符串，是玩家当前**占领/保护**的地图名（ownermap 拼写错误），属于「地图占领赛」系统 | 4 处：`tag#2274 @0x1A4B28` 初始化为 `''`；`tag#2445` 持久化；`tag#5086` 挑战者 NPC 对白；`tag#684 @0xF1242` 战斗胜利后 `owermap = nowmap` |
| `returnmap` | 返回 | **不是变量，是函数**。定义在根帧 6 `tag#2274 @0x1A4A6A`（DefineFunction2, code_size=66） | 1 处定义 |

`returnmap` 函数体（`tag#2274 @0x1A4A7E`–`0x1A4AC0`）反汇编即：

```
function returnmap() {
    if (mc_day.nowday > mc_day.allday) gotoAndStop("游戏结束");   // 0x1A4AA1
    else                               gotoAndStop(nowmap);       // 0x1A4ABC GotoFrame2
}
```

这是「战斗/事件结束后回到当前地图」的统一出口。

`owermap` 的语义证据最直接的是挑战者 NPC（`tag#5086` sprite1079，出现在雷鸣大陆/卡萨诺城/戈壁/迷梦沼泽/冰宫/亚维特岛 6 张图）的对白拼装：

- `owermap == ''` → `nowmap + "还没有保护者。"`（`@0x24DB95`）
- `owermap == nowmap` → `nowmap + "已经属于你的保护地了。"`（`@0x24DBC9`）
- 否则 → `"你是" + owermap + "的保护者。如果要挑战" + nowmap + "你将会放弃" + owermap + "保护者的资格"`（`@0x24DC08`）

**结论：`nextmap` / `owermap` / `returnmap` 都不携带地图连接信息**，任务书里「用 nextmap/owermap 推测线性结构」这条路走不通。真正的连接数据只有第 2 节的 41 个箭头实例。因此 `native_map_links.json` 里这三个字段逐图标为 `NOT_A_PER_MAP_FIELD` / `NOT_A_VARIABLE` 并附理由，而不是 `UNCONFIRMED`——我们确实解出了它们，只是它们不是连接数据。

### 4.1 进入门槛（gate）

门槛集中写在箭头剪辑的 `onRelease` 里，形如 `if (nowmap == A && map == B) { 条件不满足则 alertbox 并 return false }`。工具自动提取到 6 条，全部来自 `tag#4948`：

| 从 | 到 | 条件（反汇编） | alertbox 文案 | 偏移 |
|---|---|---|---|---|
| 皇宫 | 后花园 | `xinxi.jwdj > 0` | 只有爵位达到勋爵以上才可以进入后花园 | 0x24ABDE |
| 卡萨诺城 | 亚维特岛 | `xinxi.dj >= 70` | 亚维特岛是个十分危险的地方，70级以上才允许从卡萨诺城进入亚维特岛 | 0x24AC3E |
| 冰宫 | 雪域边境 | `mc_day.nowday % 7 == 5` 或 `king == false` | 该地方十分危险，你没有有任务不能进入雪域边境 | 0x24AC99 |
| 地下城1层 | 地下城2层 | `rw_gw1_1 or rw_gw1_2 or rw_gw1_3` | 只有消灭完怪物后才能进入下一层 | 0x24AD14 |
| 地下城2层 | 地下城3层 | `rw_gw2_1 or rw_gw2_2` | 只有消灭完怪物后才能进入下一层 | 0x24AD7E |
| 魔军帅旗 | 能量塔禁地 | `mj_zs == true` | 魔军主帅在此守护，无法进入魔军能量塔禁地 | 0x24ADD9 |

注意「亚维特岛 70 级」门槛的判定是 `nowmap == '卡萨诺城' && map == '亚维特岛'`，只卡**从卡萨诺城直接过去**这一条边；从冰宫走 `冰宫 → 亚维特岛`（tag#5921）不受这个门槛限制。alertbox 原文也是这么写的（「才允许从卡萨诺城进入亚维特岛」）。

### 5.1 起始地图

新游戏在根帧 6「开始」初始化（`tag#2274 @0x1A4B20`）：`nowmap = "雷鸣大陆"`，随后 `gotoAndStop(nowmap)`。原版**开局在雷鸣大陆，不是卡萨诺城**。

### 5.2 两张没有出口箭头的地图

- **草原2（帧 11）**：帧脚本 `tag#5195` 是 `if (nowmap == "卡萨诺城") gotoAndStop(nowmap); else { alertbox("经过一番努力，终于看到了一只可爱的娃娃"); _root.nowmap = "卡萨诺城"; }`（@0x25E423–0x25E45D）。即进入时就把 nowmap 改写成卡萨诺城，之后任何 `gotoAndStop(nowmap)`（HUD 按钮 tag#4079 或 `returnmap()`）都会把玩家送回卡萨诺城。
- **战魂封印谜宫（帧 34）**：帧脚本 `tag#6279` 只设置 `renwu._x/_y` 和 `danger = false`，没有任何跳转。回程靠**进入前**战魂探险家先写好的 `_root.nowmap = "卡萨诺城"`（tag#5855 @0x29CCDF，就在 `gotoAndStop("战魂封印谜宫")` 前一句），打完无名氏后 `returnmap()` 即回卡萨诺城。

同理，草原（帧 10）的帧脚本 `tag#5180 @0x255F06` 在进入时把 `nowmap` 写成 `"草原2"`，所以打赢雷角风牙兽后 `returnmap()` 会落到草原2。这就是「草原 → 草原2」这条边的实现方式，它没有箭头。

## 6. 与 `data/maps.json` 的差异清单

对照口径：只比对 28 张有原版对应的地图（原版 35 个 FrameLabel 中，前言/创建角色/读取游戏/开始/读取进度/战场/游戏结束 这 7 个是系统帧，不是地图）。
统计：**能对上 41 条，原版有而现有没有 4 条，现有有而原版没有 8 条**。

## 7. 三个疑点的回答

### 疑点 1：卡萨诺城 ⇄ 亚维特岛 / 卡萨诺城 ⇄ 戈壁 到底是不是单向？

**答：两条捷径原版都存在，而且都是双向的。现有数据的单向是错的。**

| 方向 | 原版是否存在 | 证据 | 门槛 |
|---|---|---|---|
| 卡萨诺城 → 亚维特岛 | 有 | tag#5406，根帧 12 depth 27 | 70 级（tag#4948 @0x24AC3E） |
| 亚维特岛 → 卡萨诺城 | **有** | tag#5977，根帧 19 depth 43 | 无 |
| 卡萨诺城 → 戈壁 | 有 | tag#5409，根帧 12 depth 36 | 无 |
| 戈壁 → 卡萨诺城 | **有** | tag#5826，根帧 16 depth 27 | 无 |

现有 `maps.json` 缺的正是加粗的两条回程边；而且现有给戈壁安的回程是「返回雷鸣大陆」，原版根本没有这条边。

### 疑点 2：雷鸣大陆有没有第三个到戈壁的出口？

**答：没有。原版雷鸣大陆只有 2 个出口，与截图 `image_1040.jpg` 完全一致。**

- 根帧 8 上 character 1071 的 PlaceObject2 记录只有 2 条：depth 12（tag#4957，`map = "卡萨诺城"`）和 depth 15（tag#4958，`map = "雷鸣矿洞"`）。
- 显示列表模拟显示帧 8 上没有从更早帧继承的箭头（帧 8 之前最近一次放 1071 就是帧 8 自己；帧 7「读取进度」的显示列表里 1071 数量为 0）。
- 反向交叉验证：戈壁一侧（根帧 16）的 2 个箭头是卡萨诺城和迷梦沼泽，也没有回雷鸣大陆的边。

所以现有的 `雷鸣大陆 → 戈壁` 和 `戈壁 → 雷鸣大陆` 两条边都是重制版新加的，原版不存在。

### 疑点 3：枢纽放射还是线性？

**答：线性链 + 两条回枢纽的捷径。v1.41 试玩清单的说法有 4 条不成立。**

原版主线的实际拓扑（全部双向）：

- **主链**（每一段都是双向）：卡萨诺城 ⇄ 戈壁 ⇄ 迷梦沼泽 ⇄ 冰宫 ⇄ 亚维特岛 ⇄ 火山 ⇄ 深渊迷宫
- **捷径**：卡萨诺城 ⇄ 亚维特岛（把链尾接回枢纽；卡萨诺城 → 亚维特岛 方向卡 70 级）
- **枢纽旁支**：卡萨诺城 ⇄ 雷鸣大陆 ⇄ 雷鸣矿洞；卡萨诺城 ⇄ 皇宫 ⇄ 后花园
- **战线旁支**（从链的中段 冰宫 分出去，不经过枢纽）：冰宫 ⇄ 雪域边境 ⇄ 魔中军阵地 ⇄ {魔左军阵地 / 魔右军阵地 / 魔军帅旗 ⇄ 能量塔禁地}
- **NPC 传送图**（只有单向回城箭头，不在链上）：草原 / 草原2 / 抽奖房 / 地下城1–3层 / PK赛场1–3层 / 战魂封印谜宫 / 树心城

从卡萨诺城能**直达**的只有 4 张：皇宫、雷鸣大陆、戈壁、亚维特岛（70 级）。清单逐条核对：

| 清单说法 | 原版实测 | 结论 |
|---|---|---|
| 戈壁 = 卡萨诺城出口 | 卡萨诺城 depth 36 有直达箭头 | **成立** |
| 迷梦沼泽 = 卡萨诺城出口 | 只能从戈壁（tag#5827）或冰宫（tag#5922）进入 | **不成立** |
| 冰宫 = 卡萨诺城出口 | 只能从迷梦沼泽（tag#5875）、亚维特岛（tag#5979）或雪域边境（tag#6102）进入 | **不成立** |
| 亚维特岛 = 卡萨诺城出口（70 级） | 卡萨诺城 depth 27 有直达箭头，且门槛正是 70 级 | **成立** |
| 火山 = 卡萨诺城出口 | 只能从亚维特岛（tag#5975）或深渊迷宫（tag#6072）进入 | **不成立** |
| 深渊迷宫 = 卡萨诺城出口 | 只能从火山（tag#6056）进入 | **不成立** |

另外要强调一点：这个「链式」结论**不是**从 `nextmap` / `owermap` 推出来的。任务书提示的那条思路走不通，因为这两个变量根本不是链表指针（见第 3 节）。链式结构是直接从 41 个箭头实例的目标地图名读出来的。

## 8. 本轮未能确定的部分（UNCONFIRMED）

`native_map_links.json` 用两个不同的哨兵值，不要混淆：

- `UNCONFIRMED`：字节码里判定不了。
- `NO_ASSIGNMENT_IN_FRAME_SCRIPT`：该帧脚本已完整反汇编（0 告警），确认**没有**这个赋值。这是阴性结论，不是未知。

逐图 `nowmap` 字段：10 张地图的帧脚本里有字面量赋值（草原、草原2、皇宫、抽奖房、雪域边境、地下城1/2/3层、树心城，加上根帧 6 的初始化），其余 25 个帧标 `NO_ASSIGNMENT_IN_FRAME_SCRIPT`。这不是解不出来——那些地图是靠箭头进入的，箭头 `onRelease` 在 `gotoAndStop` 之前已经写好 `_root.nowmap`，帧脚本不需要再写一次。反过来，会在帧脚本里补写 `nowmap` 的，恰好都是靠 NPC 传送进入的地图（传送方只调 `gotoAndStop`，不写 `nowmap`），逻辑自洽。

真正标 UNCONFIRMED 的只有以下几项：

1. **草原2 与战魂封印谜宫在「不触发战斗」时的离开手段**。两张图都没有出口箭头，已确认的回程依赖 `returnmap()`（战斗/事件结束后调用）以及常驻 HUD 按钮 button 829 的 `gotoAndStop(_root.nowmap)`。button 829 位于 sprite832 内、放置在根帧 6，随 HUD 常驻到所有地图，但**它的显示/隐藏条件本轮没有审计**，所以无法断言玩家在任何时刻都能用它脱离这两张图。
2. **`map_race` / `mapreward` 的完整规则**。已确认二者都是布尔量、都参与存档持久化（tag#2445）、都由挑战者 NPC（tag#5086）改写，但占领赛的完整判定链不在本轮范围。
3. **「战场」（根帧 36）内部逻辑**。它不是地图（帧脚本不设置 `renwu` 坐标），是战斗场景；其内部 `zhanchang` 剪辑的时间轴本轮未审计。
4. **重制版独有的 22 张地图**无原版对照物，无法判定对错。

以下几项曾经存疑，本轮已**排除**，记录在此以免重复排查：

- **箭头会不会在运行时被隐藏？** 不会。41 个箭头实例中只有 3 个带实例名（`escape_btn`＠帧10 d12、`toMap2`＠帧28 d8、`escape_btn`＠帧35 d20），而全片 817 个动作块里**没有任何一处引用这三个名字**；sprite1071 自身也不写 `_visible`。门槛不是靠隐藏箭头实现的，是点击后弹 alertbox 并 `return false`（第 4.1 节）。
- **有没有第三种切图机制？** 没有。全片对根帧标签的字面量跳转共 31 处（第 5 节已全列），动态跳转只有 `gotoAndStop(map)` 和 `gotoAndStop(nowmap)` 两种。
