# 原创美术生成提示词包

用途：本目录供项目负责人把单个 Markdown 中的提示词复制到 GPT 网页版，生成**原创**游戏资源。它不是开发任务输入，也不是自动导入清单；正式开发模型只会在资源定稿后收到纯文本 manifest、资源路径、尺寸、哈希、用途和审批状态。

截至本次覆盖审计，库内有 **725 个 Markdown 文档**，其中 **633 份是单个可生成资源的独立提示词**。这不是“只需要生成 633 张”的要求：有些是必需基础资源，有些是可选增强、动画、封面和剧情预留。对已批准的 v1.42–v1.55 任务书，所有明确视觉域均已有独立提示词入口；逐版本依据见 [00_未来版本美术覆盖审计.md](00_未来版本美术覆盖审计.md)。

## 使用顺序

1. 先阅读 [00_统一风格与导出规范.md](00_统一风格与导出规范.md)。
2. 先生成并选定一张风格校准图；不要同时批量生成全部资产。
3. 每次仅复制一个资产文档中的“可直接复制提示词”。
4. 生成后保留原始文件；由 PM/SE 选图、裁切、命名、去底/转换、计算哈希并建立 manifest。
5. 未经 PM/SE 书面批准，任何生成文件不得引用进 Godot 场景或提交为生产资源。

## 总约束

1. 所有角色、怪物、场景、图标必须为原创设计；不复刻、不描摹、不混入现成游戏人物、Logo、UI 文案或水印。
2. 目标观感是“复古暗黑奇幻、早期中文奇幻 MMORPG 的清晰像素插画感”，而不是复制某款特定游戏的资产。
3. 不在生成图内写任何可读文字、数字、符号、水印或界面。
4. 地图背景中不画 NPC、怪物、角色、宝箱、可点击箭头或 UI；这些由 Godot 运行时叠加。
5. 透明资源优先要求透明 PNG；若网页版不能可靠透明，改用指定纯色抠图背景，且不得包含阴影、地面、渐变或该纯色边缘。
6. 每个文件名、尺寸、裁切方式和最终路径以单独文档为准；不要自行改变比例。
7. 动画精灵表与表情条必须人工拆格、验脚底基线和一致性。不合格时不导入，继续使用已批准的静态图。
8. v1.42 尚未对 2.2/2.3/2.4 完成资源审计；若审计发现已有可合法复用素材，标为 `not_needed_after_audit`，不强行重复生成。

## 生成后必须记录的文本信息

每张定稿图都要在后续 manifest 登记：`asset_id`、生成日期、原始文件名、最终路径、像素尺寸、裁切区域、哈希、用途、来源分类 `original_generated`、审批状态。

本提示词包只准备资源，不改变当前 v1.41 生产内容、数值、场景、存档或发布包。
